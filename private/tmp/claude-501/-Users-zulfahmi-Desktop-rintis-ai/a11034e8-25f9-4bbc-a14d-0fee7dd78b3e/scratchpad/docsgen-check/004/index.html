Build plan 004

u60-monitor — Editorial Redesign (plan-004)

Implement the Claude-Design editorial restyle of the speed screen in ten foundation-first TDD cycles: bundle Space Grotesk + Space Mono offline, swap the teal Material seed for a fixed-hex editorial token set (lime download / sky upload), restyle the feed-state header, build a side-by-side speed twin with count-up, extend the existing CustomPainter sparkline (peak label + mm:ss axis + reconnecting em-dash) — keeping charting in-house per ADR-0007 — restyle the battery section with a charge-cap tick, fold signal + uptime + clients into a new 3-cell footer, and assemble the editorial screen PRESERVING plan-002’s per-tile freshness. ZERO new pubspec PACKAGE deps (fonts are local assets); ZERO security-tier cycles; ADR-0002 base-URL invariant stays dormant.

10 TDD cycles 5 parallel batches ~45% — P4.A (4.1 core ‖ 4.2 fonts) and P4.C (4.4 header, 4.5 twin, 4.6 chart-visual, 4.8 battery, 4.9 footer — file-disjoint, additive) each collapse to ~1 wall-step. The serial spine is fonts → tokens → chart-visual → chart-contract → assembly (4.2 → 4.3 → 4.6 → 4.7 → 4.10); everything else fans out around it. 4.3 is the single gate every UI cycle waits on. wall-time saved 10 / 10 shipped

Context

plan-004 is the editorial-redesign plan for u60-monitor. plan-001 shipped the live-speed MVP, plan-002 the Glance Dashboard (history sparkline, battery, signal, status strip) on one no-scroll screen, and plan-003 paid down the debt tail. plan-004 implements a cohesive visual overhaul from a Claude-Design redesign (project 43605a77, files U60 Monitor.dc.html + U60 Screen.dc.html) — see §Design source. It is a restyle, not a re-platform: every metric is already sourced and the poller orchestration in lib/app.dart is untouched.

The redesign in one breath. Monospace-driven editorial look: Space Grotesk (display + big numerics) + Space Mono (labels/captions), bundled offline. Near-black #0A0A0B ground, lime #A3E635 download / sky #38BDF8 upload accents, dark-default + light token sets. Layout top→bottom: feed-state header (U60 / MONITOR + live/stale/reconnecting indicator) → side-by-side DOWNLOAD | UPLOAD twin (66px/27px split numerics, count-up) → 104px dual-line throughput sparkline (download area-fill + line, upload line, PEAK label, −2:00 / NOW axis) → battery row (44px %, charge-cap tick) → combined NETWORK / UPTIME / CLIENTS footer.

Data-reality: every design field is REAL. A fanout audit (8 agents) cross-checked each design field against the agent contract in lib/core/*_snapshot.dart — download/upload (SpeedSnapshot), operator + dBm + 5G-NSA + bars (SignalSnapshot), uptime (DeviceSnapshot + formatUptime already emits 3h 12m), battery % + charge-cap (BatterySnapshot.chargeLimitPct/chargeLimitEnabled), clients (ClientsSnapshot.count). Nothing decorative; no honest-mock copy needed. Two design values are illustrative, not literal: the “CAP 80%” cap value is live (chargeLimitPct, shown only when chargeLimitEnabled) and the “−2:00” window is dynamic (−0:42 until the 120-sample ring fills). Null operator / null rsrpDbm must render gracefully (no literal null).

The three feed states already exist. FreshnessState.live/stale/reconnecting has been a first-class enum since plan-001 Cycle 1.7 (MonitorHeader._DotIndicator already has the breathing live pulse + reconnecting ring; MonitorColors already carries statusLive/Stale/Reconnecting tokens). The redesign restyles these states — it does not introduce a fourth.

Charting stays in-house (ADR-0007). The user asked whether to keep the hand-rolled CustomPainter or migrate to a package. A four-way research fanout (fl_chart / graphic / syncfusion / keep-and-extend) judged against this exact need — a small 104px glanceable dual-line sparkline, offline, pure-Dart lib/core discipline — concluded keep-and-extend. The existing SpeedHistoryPainter (≈327 LOC) + tested sparklinePoints geometry already implement the structurally hard parts (dual-trace, stale-gap honesty via _forEachSegment, shared auto-range, identity-gated shouldRepaint); every redesign delta closes in ≈50–110 incremental LOC. fl_chart/graphic/syncfusion each add +200–500 KB to an offline app for zero feature this chart needs; fl_chart additionally couples the never-lie gap invariant to FlSpot.nullSpot semantics and forces a Flutter-floor bump. See §Charting decision + ADR-0007.

Per-tile freshness is PRESERVED (user-confirmed). The design mock dims the WHOLE screen on stale and blanks ALL values on reconnecting (a single global feed-state). The user chose to keep plan-002’s per-tile-independent freshness (2.12/2.13): the speed-stream feed-state drives ONLY the header + speed twin + sparkline (the speed-derived surfaces); battery / signal / uptime / clients each keep their OWN isStale + StaleFade, so a still-fresh battery stays lit during a speed-only reconnect. ADR-0009 records this as an explicit rejection of global feed-state, NOT a reversal. This lowers risk — the existing per-tile wiring is reused, not rebuilt.

Ten cycles, five batches, additive (strangler) migration. New widgets (speed_twin.dart, footer_triplet.dart) and the new token set are added ALONGSIDE the old ones so the un-migrated screen compiles through the whole component batch; the superseded speed_card.dart / signal_tile.dart / status_strip.dart and the orphan tokens are deleted only at integration (4.10). Foundations first: P4.A core display logic (4.1) ‖ offline fonts (4.2); P4.B theme token system (4.3, gates all UI); P4.C five file-disjoint component cycles (4.4 header, 4.5 twin, 4.6 chart-visual, 4.8 battery, 4.9 footer); P4.D chart data contract (4.7, header/footer + reconnecting em-dash); P4.E screen assembly + orphan cleanup (4.10). Critical path = 4.2 → 4.3 → 4.6 → 4.7 → 4.10.

ZERO new pubspec PACKAGE deps; ZERO security-tier cycles. Fonts are local .ttf assets, not a package — google_fonts is rejected (it fetches from fonts.gstatic.com at runtime = unacceptable for a LAN-only offline app; raw .ttf bundling is zero-dependency, deterministic, OFL-licensed). No cycle touches auth/token/password/base-url; the ADR-0002 base-URL invariant stays dormant and carried (same posture as plan-003). A package add or a base-URL setter is an out-of-bounds STOP.

TDD cycle format

Architecture-review value on every cycle is mandatory (missing field → STOP). No cycle is security-tier; the architect (on the gated cycles) and the reviewer (all cycles) must still confirm this per cycle, not assume it.

Charting decision (in-house vs 3rd-party)

The user asked whether to keep the in-house chart or migrate to a package. A research fanout (Flutter-expert agents + an opus architect judge) assessed four options against the Mandatory Research Standard, scored on the actual need — a 104px glanceable dual-line throughput sparkline, fully offline, with the pure-Dart lib/core discipline:

Option License Offline App-size delta Design fit Verdict
keep-custom first-party yes 0 KB all gaps close in ≈50–110 LOC over existing files; gap-honesty stays structurally enforced CHOSEN
fl_chart 1.2.0 MIT yes +200–400 KB close fit, but couples the never-lie gap invariant to FlSpot.nullSpot; forces Flutter floor 3.27.4 rejected (sanctioned fallback for a future interactivity need)
graphic 2.7.0 MIT yes +200–400 KB grammar-of-graphics engine; orphans the tested geometry; sparse releases, 72 analysis warnings rejected
syncfusion_flutter_charts 33.x proprietary yes >500 KB dual-line needs the heavy SfCartesianChart; license key embedded in source rejected

Trade-off (named): we keep-and-extend the hand-rolled painter over fl_chart (the only close-fit package) because the simplest, most reversible option already clears the bar and no evidence shows it fails — we knowingly give up out-of-the-box interactivity (touch, zoom, tooltips, grids), none of which is in scope for a glanceable monitor. Reversibility: near-zero and unchanged — the SpeedHistoryChart widget boundary stays the sole integration surface, so a future swap to the documented fl_chart fallback is a single-file change with no new lock-in. Recorded in ADR-0007 (also covers offline font bundling).

Out of scope (plan-004)

  • Global feed-state (whole-screen dim on stale / blank-all on reconnecting) — the design mock implies it; the user chose to KEEP plan-002’s per-tile-independent freshness. Recorded as a deliberate rejection in ADR-0009, not a deferral.
  • A base-URL / Settings setter — not added (keeps the plan out of the security tier per ADR-0002). The invariant is carried, not discharged.
  • A charting package — rejected per ADR-0007 (keep-and-extend the CustomPainter). fl_chart stays the documented fallback for a future interactivity need only.
  • google_fonts — rejected (runtime network fetch breaks the offline guarantee). Fonts are local .ttf assets.
  • Sparkline draw-in / point-append animation — the FU-17 no-ImplicitlyAnimatedWidget won’t-do invariant stands; 4.6/4.7 preserve the guard.
  • Chart interactivity (touch / zoom / tooltips / grids) — out of scope for a glanceable monitor.
  • The two-up half-width Battery + Signal Row (plan-003 FU-18) — the new design supersedes it with a full-width battery row + a 3-cell footer; the old open question is moot.
  • A low-SoC battery accent colour — the design battery bar is monochrome fg; the red token exists but is unused on this screen. A low-battery cue is a possible future cycle (see §Open questions).
  • On-device Samsung S22 / iOS device-verify smokes — a manual human deploy pass; no agent drives a physical phone. Tracked in §Cycle follow-ups.
  • Any new pubspec PACKAGE dep — there is no dependencies:-touch cycle; a mid-plan package add is an out-of-bounds STOP. (4.2 touches pubspec.yaml for the fonts: block + assets ONLY.)

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
