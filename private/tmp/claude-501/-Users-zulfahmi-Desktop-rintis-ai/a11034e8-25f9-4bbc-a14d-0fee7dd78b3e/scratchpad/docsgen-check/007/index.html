Build plan 007

u60-monitor — Numeric-text content transitions (plan-007)

Replace the first-load-only count-up ramp with a faithful SwiftUI .contentTransition(.numericText()) morph that fires on EVERY value change, applied to every live numeric readout in the app. The motion is decoded FROM PIXELS (a 169-frame frame-by-frame capture, docs/rnd/swiftui-numerictext-animation/): each changed glyph column does blur + scale + downward slide + asymmetric cross-fade, digits resolve left-to-right (a stagger), and the number width reflows on a digit-count change. Built as one reusable primitive over THREE cycles — 7.1 a pure-Dart right-aligned glyph-diff (lib/core/numeric_transition.dart, unit-tested), 7.2 the AnimatedNumericText core roll (drift+scale+fade+stagger, saveLayer-free at rest), 7.2b its blur + animated reflow + perf tiering — then adopted across all five numeric surfaces over four cycles (7.3 SpeedTwin, retiring the old CountUpText; 7.4 BatteryTile; 7.5 DataUsageSection; 7.6 FooterTriplet + SpeedHistoryChart). The enter-live ‘0’-baseline count-up hack is removed. ZERO new pubspec deps.

10 TDD cycles 3 parallel batches Low–moderate. The serial spine is 7.1 → 7.2 → 7.3 (each depends on the prior). The three remaining adoptions (7.4, 7.5, 7.6) depend only on 7.2 and are file-disjoint, so they COULD parallelise in worktrees — but the run executes them SEQUENTIALLY on main because each cycle's full `flutter test` gate is cross-attributable in a shared tree (the plan-004/005 lesson). One commit per cycle. wall-time saved 10 / 10 shipped

Context

What the user asked for. Today the DL/UL speed numerals “animate” only once — on entering the live state, a count-up ramp scans from 0 to the first value (the CountUpText widget + a post-frame '0'-priming trick in SpeedTwin). Live→live ticks then snap with no motion, and no other number in the app animates at all. The request: give every numeric readout a SwiftUI .contentTransition(.numericText())-style transition — a per-digit morph that fires on every value change, not just first load — and apply it to all numeric texts in the app.

What that means concretely — decoded from the actual pixels. An earlier attempt to spec this from web docs got the motion wrong twice (it landed on a plain “odometer slide + fade” and then explicitly dropped blur/scale/width). A frame-by-frame decode of the real effect (169 captured frames, see §Motion spec) is authoritative and shows a RICHER, layered per-column transition: a changed glyph column plays gaussian blur (heavy at mid-transit, sharp at rest) + scale (incoming grows 0.6→1.0, outgoing shrinks) + a downward vertical slide (new glyph enters from ABOVE, old exits BELOW — a FIXED direction, the same for increases and decreases, NOT a value-driven odometer) + an asymmetric cross-fade (outgoing gone by ~65 % t); changed columns resolve left-to-right (a stagger); and the number width reflows over ~3–4 frames on a digit-count change. Unchanged columns stay frozen-sharp. It remains a presentation effect: the value passed in is unchanged, the exact target string always settles on screen, Semantics announces the raw value, reduced-motion is honoured — the same discipline CountUpText followed; plan-007 only changes the motion.

The shape of the work. One reusable primitive, then adoption:

  1. The glyph-diff is pure logic and belongs in lib/core/ beside sparkline_geometry.dart / format.dart — a right-aligned column diff of two strings returning, per NEW-string glyph column, the old glyph (or null if the number grew), a changed flag, and an overall roll direction (+1 / -1 / 0) from a numeric compare. Pure Dart, no flutter import, fully unit-testable (the triangle: equal, single-digit change, grow, shrink, decimals, minus sign, non-numeric placeholder, empty). → Cycle 7.1 (lib/core, arch-gated).
  2. The widget, split into a cheap core + a perf-sensitive polish. 7.2 builds the AnimatedNumericText CORE roll off ONE shared AnimationController: per changed column a Stack(outgoing, incoming) doing the fixed top-enter/bottom-exit drift + scale + asymmetric color-alpha cross-fade, with a left-to-right stagger; unchanged columns stay static; at rest / under reduced motion it collapses to a single Text (zero saveLayer). 7.2b adds the two saveLayer-bearing, on-device-tuned effects the frames prove real but that cost GPU at 1 Hz: the gaussian blur (cell-level ImageFiltered, gated on isAnimating, capped sigma, kill-switch) and the animated width reflow (FittedBox-safe, controller-driven), plus the perf tiering. Splitting them lets 7.3’s SpeedTwin adoption land on the cheap core first and gate blur behind the tiering decision. → Cycles 7.2 + 7.2b (lib/ui, arch deferred to 7.1). See §Motion spec.
  3. Adoption, one surface per cycle, wrapping every live number in the primitive and (7.3) retiring CountUpText: 7.3 SpeedTwin (whole + fraction, drop the '0'-prime count-up hack), 7.4 BatteryTile (SoC %, CAP %), 7.5 DataUsageSection (used hero, percent, OF-caption, ▼rx ▲tx split, resets-day), 7.6 FooterTriplet (CLIENTS count, −dBm, uptime) + SpeedHistoryChart (PEAK value, elapsed window). See §Numeric-surface inventory for the exhaustive map that satisfies the “ALL numeric texts” requirement.

Why a new primitive and not an extension of CountUpText. CountUpText interpolates the numeric value (a tween from → to, re-rendered each frame via toStringAsFixed). The morph interpolates glyph positions + blur/scale/opacity, not the value — a categorically different mechanism. Bolting per-glyph motion onto the value-tween would be two animation models in one widget. The clean move is a purpose-built primitive; CountUpText’s sole caller is SpeedTwin, so 7.3 migrates it and deletes CountUpText (no dead code — review-checklist §Clarity).

Boundary honoured throughout. lib/core/numeric_transition.dart (7.1) is pure Dart — a flutter/material/dart:ui import there is an instant review BLOCKER. Formatting stays where it is (splitRate / formatBytes / formatUptime in lib/core/format.dart + device_snapshot.dart); the primitive animates the already-formatted string and never re-formats. ZERO new pubspec deps — the effect is built entirely from framework primitives already available: AnimationController, Transform.translate / Transform.scale, ImageFiltered + ImageFilter.blur, ClipRect, Stack, RepaintBoundary, plus AnimatedSwitcher for the neutral cross-fade only.

Security-tier ruling

No cycle in plan-007 is security-tier. Every cycle is presentation-only: a pure string→glyph-diff (7.1) and Flutter animation widgets (7.2–7.6). None touches authentication, secrets, cryptography, untrusted-input parsing into an injection sink, file upload, multi-tenant isolation, webhook signatures, or any LLM surface — none of the .claude/rules/cycle-orchestration.md §Security-tier list. The animated value is an already-formatted display string produced by the existing (already-reviewed) core formatters; the primitive never re-parses network input, never touches the token/secret path, and adds no I/O.

7.1 still carries a top-tier (opus) architect gate — but as a QUALITY decision (a new cross-cutting primitive + a per-tick animation cost + an ADR), not a security requirement. This is the honest distinction from plan-006, whose fixes were none because they reused an existing reviewed helper; 7.1 introduces new logic + a new animation model, so it earns a gate. 7.2 defers to that verdict; 7.3–7.6 are none (mechanical adoption of the reviewed primitive).

Motion spec (architect-locked at 7.1) — FRAME-ACCURATE from the 169-frame capture

Retention note (2026-07-19): docs/rnd/swiftui-numerictext-animation/ now holds only the 14 frames cited as exhibits below and in ADR-0014 (42–45, 70–71, 75, 103–104, 124–125, 144–146). The other 155 were pruned when the folder was brought under version control, and no copy survives. The decode described here was performed over the full 169 and its conclusions stand; it simply can no longer be re-derived from this repo. See §Open questions on the roll-direction item, which this forecloses.

This REPLACES the earlier web-doc-derived spec (and its “odometer” successor). A frame-by-frame decode of Apple’s Text(n).contentTransition(.numericText()) — 169 frames @ 0.03 s in docs/rnd/swiftui-numerictext-animation/, workflow wf_41da3e60-cd6 — is authoritative and proves the prior locks wrong on FOUR points: blur, glyph scale, and animated width-flow are all REAL and present, and the roll is a FIXED top-enter/bottom-exit, not a value-direction odometer. The effect is a per-column blur + scale + asymmetric opacity cross-fade with a downward slide and animated width reflow, staggered left-to-right — not a plain slide+fade. Proof it is intrinsic (not GIF/capture blur): in the SAME frame the settled sibling digit and the razor-sharp blue reference button stay crisp while only the transiting column is smeared (frames 42–45, 75, 103, 124–125, 144–146). ADR-0014 is authored to match. The build splits: 7.2 = the core roll (drift + scale + fade + stagger, saveLayer-free at rest); 7.2b = blur + animated reflow + perf tiering (the saveLayer-bearing, on-device-tuned half).

Controller architecture

  • One AnimationController per AnimatedNumericText instance (SingleTickerProviderStateMixin), ~300 ms, base easeOutCubic. Every layer — per-column drift, scale, opacity, the stagger, the blur sigma, the reflow width — reads from this ONE clock (one dispose, one hasRunningAnimations, deterministic pumpAndSettle).
  • Left-to-right stagger: changed column i (counting changed columns from the LEFT) gets CurvedAnimation(Interval(i*0.12, min(1, i*0.12+0.7), easeOutCubic)) → the observed ~3–5-frame (90–150 ms) cascade; the leftmost changed digit settles first (transient reads like 31 during 71→37, 47 during 37→4).
  • At rest / reduced motion: a single plain Text(value) — no Stack, no clip, no blur, no saveLayer (the perf floor; ~700 ms of every second on the DL/UL twin).
  • AnimatedSwitcher retained ONLY for direction == 0 (—↔value, empty, mixed 3d 4h) whole-string cross-fade (no slide/scale/blur).

Compositing order (outer→inner, one changed cell)

  • RepaintBoundary [whole number] → Semantics(label:value)+ExcludeSemantics → Row(mainAxisSize.min, centerLeft) of columns (unchanged = plain Text; changed = cell) → row-level ClipRect with vertical slack (NOT per-glyph — height:0.82 on the 66 px style crops ascenders) → per changed cell: SizedBox(tabular advance × full line box) → ImageFiltered blur (7.2b, gated on isAnimating) → Stack(outgoing, incoming) → per glyph: Transform.translate (drift) → Transform.scale → color-alpha fade (Text color opacity, NOT an Opacity widget — no per-glyph saveLayer) → Text.

Direction geometry (CORRECTED — fixed top-enter, NOT a value odometer)

  • New glyph enters from ABOVE, old glyph exits BELOW — on BOTH increases and decreases. Every transition in the capture (increase 0→149, 56→76; decreases 149→59, 76→71, 71→37) is top-down. Do NOT flip by value sign — the prior “increase = both up / decrease = both down” odometer is contradicted by the frames.
  • Incoming dy: −0.55 → 0 (cell heights, easeOut); outgoing dy: 0 → +0.55 (easeOut). The 7.1 direction ∈ {+1,−1,0} is still computed (it drives the neutral 0 cross-fade) but does NOT set the slide axis.

Scale (7.2, BUILD IT)

  • Incoming glyph scale 0.6 → 1.0; outgoing scale 1.0 → 0.55. Transform.scale off the same column sub-animation, composed with the drift. The frames show incoming digits entering visibly small-and-high, then growing down into the cell (frames 42, 44, 45, 70–71, 103–104, 144–145).

Offset + opacity kinematics (7.2)

  • Position easeOutCubic. Opacity ASYMMETRIC: incoming 0 → 1 over full t; outgoing 1 → 0 gone by ~65 % t (the exiting glyph is gone before the overlap peak — no muddy double-exposure). Fade via Text color-alpha, never an Opacity widget (no per-glyph saveLayer). This asymmetry is the one thing the prior spec had right.

Blur (7.2b, BUILD IT — the signature “more”)

  • Heavy gaussian on the transiting glyph, peaking at mid-transit (t≈0.4–0.55), zero at both ends — σ = peakSigma · sin(π·t). Near-isotropic with a mild vertical bias. Peak ≈ 4–8 px at 66 px (capped lower on the fast twin — see tiering).
  • Applied once at the CELL level (wrapping the outgoing+incoming Stack, NOT per glyph): ImageFiltered(imageFilter: ImageFilter.blur(sigmaX:σ, sigmaY:σ, tileMode: TileMode.decal)), gated enabled: _controller.isAnimating && σ>0.01 so an idle number holds ZERO saveLayer. Force-off under reduced motion / the perf kill-switch. Paint-only — never participates in FittedBox measurement or tabular width.

Width reflow (7.2b, ANIMATE IT — FittedBox-safe)

  • Digit-count changes reflow over ~3–4 frames (~90–120 ms), NOT a one-frame snap (0→149 widens, 149→59 narrows, 37→4 collapses — the width holds then lerps). Same-digit-count changes show NO width change (tabular holds advance constant).
  • Drive the leading cell’s width off the same controller (grow 0→advance / shrink advance→0), and reserve the FittedBox child constraint at the measured max(from,to) width so the FittedBox re-fits against a MONOTONE width and the settled digits never zoom/wobble. NEVER nest AnimatedSize inside the load-bearing FittedBox(scaleDown) guards (speed_twin.dart L333; data_usage_section.dart L297/L341/L388) — a per-frame-lerping child size makes the FittedBox re-fit every frame.

Timing

  • Full onset→settle 8–11 frames (~240–330 ms) for multi-digit / digit-count changes; 5–7 frames (~150–210 ms) for a single glyph. Blur body ~5–7 frames. All < the 1 s tick; a mid-roll change retargets (forward(from:0)).

Width stability

  • The style MUST carry FontFeature.tabularFigures() (present on the surfaces that matter); the primitive forwards it verbatim. A non-tabular caller style makes the FittedBox rescale every frame → REVIEW note.

Reduced motion

  • MediaQuery.disableAnimations true → build returns plain Text(value); didUpdateWidget sets _controller.value = 1 (never forward) so no ticker starts and hasRunningAnimations stays false; didChangeDependencies snaps an in-flight controller to 1 on a runtime toggle. Blur force-off. Mirrors StaleFade/CountUpText. Do NOT use switcher-with-Duration.zero (a zero-duration controller can tick once → momentarily true). Final value always the exact string.

Semantics

  • Announce the final value once; excludeSemantics the glyph children (never per-frame glyph nodes or the transient stagger read). Under the surfaces’ composed excludeSemantics parents the primitive’s label is suppressed → no double-announce. Per-frame glyph exposure = BLOCKER a11y regression.

Performance tiering (blur KEPT but bounded — the user decides the battery/fidelity point)

  • Slow surfaces (battery 5 s, clients 10 s, data 30 s, PEAK, uptime): FULL effect — blur + scale + drift + opacity + reflow. Concurrency ≈ 1 glyph, low cadence ⇒ ~free.
  • Fast 1 Hz DL/UL twin: scale + drift + asymmetric opacity + animated reflow run unconditionally (near-free — Transform + color-alpha, no extra layers). Blur ships cell-level, enabled: isAnimating, capped blurSigma (~3–4 px, exposed as a param), TileMode.decal, under the whole-number RepaintBoundary — ~4 blurred cell-rasters for ~300 ms then plain Text for ~700 ms each second. A runtime kill-switch drops blur to 0 under battery-saver / sustained thermal / reduced-motion.
  • Honest cost: the dropped-frame risk is low (a 66 px σ≈4 gaussian on ~4 small cells fits the 16.6/8.3 ms budget); the real concern is THERMAL/BATTERY accumulation from a saveLayer+gaussian every second on an always-on tool. Bounded, not eliminated. The product call — default blurSigma on-capped vs off-with-flag on the twin — is an §Open question for the user + a thermal soak test.
  • REVIEW gate: pump past duration → hasRunningAnimations false (deterministic under one controller); idle asserts ZERO saveLayer; no dropped frames on the changed flow; the animated reflow adds no overflow at 360 dp / 1.3×.

Out of scope (plan-007)

  • On-device visual verification — a human deploy-pass (S22 Android + iPhone) confirming the morph reads well on real hardware at the real feed cadence. Automated gates run in-session; no agent drives a physical phone. Tracked, not a cycle.
  • Per-surface duration/curve tuning beyond the 7.1 lock — if the on-device pass wants a different feel per surface, that is a follow-up, not a re-architecture.
  • Animating non-numeric transitions (unit-tier swaps Kbps↔Mbps, charge-word changes, RAT-label changes) — out of scope; those stay instant. The primitive only rolls glyph columns of the passed string.
  • Chart trace animation — the sparkline path stays repaint-on-poll (ADR-0004); plan-007 animates text only, never the CustomPainter traces.
  • Any change to formatting, polling, or the core data model — plan-007 is skin-deep; it consumes the exact strings the formatters already produce.

Standing invariants preserved

  • pure-Dart lib/core boundary upheld — 7.1’s numeric_transition.dart imports no flutter/material/dart:ui.
  • never-show-0 / last-known + stale honoured — the primitive animates whatever string it is given; — / placeholder states cross-fade, they never roll a fake 0. The removed '0'-prime hack was the ONLY place a transient 0 appeared; deleting it makes the invariant cleaner, not weaker.
  • ADR-0009 per-tile freshness / ADR-0010 sticky footer UNTOUCHED — adoption wraps Text nodes in place; no layout, no stale-wiring, no footer-pin change. Adoption cycles must not grow a row’s height (tabular width-stability + same font size ⇒ same metrics) — REVIEW checks no new overflow at 1.3× text scale.
  • Reduced-motion respect — every animated surface already gates on MediaQuery.disableAnimations; the primitive centralises that, and adoption never introduces an un-gated animation.
  • Semantics composition (excludeSemantics composed labels on SpeedTwin / Battery / Data / Footer / Chart) — preserved verbatim; the primitive’s own Semantics sits UNDER those excluded parents, so nothing is announced twice.
  • no test weakening — 7.x cycles only ADD tests (and migrate CountUpText’s tests to the primitive in 7.3); no existing assertion is relaxed to fit the new motion.

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
