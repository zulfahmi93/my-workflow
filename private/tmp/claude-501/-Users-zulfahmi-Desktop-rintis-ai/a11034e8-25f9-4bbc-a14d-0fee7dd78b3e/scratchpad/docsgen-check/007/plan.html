7.1

Glyph-diff core — right-aligned per-column numeric diff

flutter-expert architect: required (top)

Create lib/core/numeric_transition.dart — a pure-Dart function that diffs two already-formatted display strings into per-glyph-column deltas for the AnimatedNumericText widget (7.2). Right-aligned: numbers grow and shrink at the LEFT, so column index runs from the right edge. For each column of the NEW string, report the glyph, the OLD glyph at the same right-index (or null when the new string is longer there — a glyph “entering”), and whether it changed. Compute one overall roll direction from a numeric compare of the two strings: +1 when the new magnitude is larger (roll up), -1 when smaller (roll down), 0 when either endpoint does not parse as a number (neutral cross-fade — e.g. the — placeholder, an empty string, or a mixed string like 3d 4h). Normalise U+2212 MINUS SIGN to ASCII - before parsing so signed dBm/temperature strings compare correctly.

Suggested surface (RED author confirms the exact names against the widget’s needs in 7.2, and writes assertions against the verified shape — not this sketch): a GlyphDelta { String glyph; String? previous; bool get isChanged => previous != glyph; } and a NumericDiff { List<GlyphDelta> glyphs; int direction; } returned by NumericDiff diffNumericGlyphs(String from, String to), glyphs ordered left-to-right to match the NEW string.

Pure Dart only — a flutter/material/dart:ui import here is an instant review BLOCKER (this file sits beside sparkline_geometry.dart / format.dart). No new deps. All prior core tests stay green.

De-muddy the fast-twin morph — lower blur sigma + de-overlap the fade

Keep the sin(π·t) blur SHAPE, the reduced-motion off-switch, and the zero-saveLayer-at-rest gating.

Digit-drop reflow — progressive width reclaim, no hold-then-snap

flutter-expert architect: required (top)

Fix the digit-count-DROP reflow so a dropped place reclaims its width PROGRESSIVELY over the roll instead of holding the old (wider) footprint then snapping narrow at the end. Evidence: docs/rnd/swiftui-numerictext-animation-issues-1/ (frames 40–50) + -issues-3/ (frame 11) — DL 132.4 → 97.4 (a 3→2 digit drop) and UL 30.8 → 18.3.

Root cause (lib/ui/widgets/animated_numeric_text.dart): a shrinking place — the _shrinkPrefix leading glyph(s) a drop discards, and any previous == null grow — routes through _reservedReflowSlot, whose OUTER SizedBox(width: glyphAdvance) is pinned at the glyph’s FULL measured advance for the WHOLE roll; only the INNER OverflowBox/Align(widthFactor: reveal) collapses (reveal = 1 − t for a shrink). So for ~300 ms the whole-number stays as wide as the old 3-digit value with a blank gap where the dropped digit was, the sibling fraction AnimatedNumericText is pushed right the whole time, and at settle the widget reverts to _buildStatic (narrower) → the width SNAPS, the fraction jumps left, and the enclosing FittedBox(scaleDown) re-fits (a visible re-zoom). The CONSTANT-outer design is deliberate (FittedBox re-fits once per end, not per frame — the _reservedReflowSlot doc) but on-device it trades smooth reflow for a hold-then-snap.

The fix mechanism is the 7.9 ARCHITECT’s call (arch-review required) — it must NOT reintroduce the per-frame FittedBox re-fit / settled-digit wobble that the constant-outer design avoided, must NOT grow the row height (the standing 7.2 invariant), and must keep grow-a-place correct (grows currently reserve-final-then-reveal, which reads fine — do not regress them). Candidate directions the architect weighs: (a) stabilise the WHOLE run’s outer width at max(from,to) advance so the FRACTION never moves and the collapsing gap lives only INSIDE the whole-number box; (b) a monotone-shrinking outer width with a test PROVING FittedBox scale is invariant for values within the column (common case fits unscaled → no wobble); © right-align the whole run and collapse leftward. Whichever is chosen, AMEND docs/adr/0014-numeric-text-transition.md with the drop-reflow resolution. This cycle RESOLVES the 7.2b/7.5 “does the animated width reflow survive the FittedBox guards” open-question with the on-device answer.
