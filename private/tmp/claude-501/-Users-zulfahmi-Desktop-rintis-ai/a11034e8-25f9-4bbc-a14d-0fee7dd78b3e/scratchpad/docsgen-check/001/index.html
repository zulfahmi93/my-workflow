Context

u60-monitor is a personal Flutter app (Android + iOS) that shows live cellular upload / download speed from a ZTE U60 Pro 5G modem. It is a deliberately lightweight, speed-first thin client over the zte-agent HTTP API already deployed on the modem (from the separate open-u60-pro project) — NOT a re-clone of that project’s full native dashboards.

Why a phone app (decided by research, not familiarity). The U60 Pro is a portable, battery-powered hotspot. The phone is the only client reliably joined to the modem’s WiFi wherever the user carries it; every Mac-side option (menu-bar, Tauri, CLI, Flutter-desktop) is live + glanceable only at the desk and goes dark exactly when a portable hotspot matters. Native Flutter HTTP also sidesteps the agent’s missing CORS headers, which double-block any browser-origin page. Trade-off accepted: a phone app is live-when-open, not glanceable — a free always-on 1s widget is OS-infeasible (WidgetKit ~40–70 reloads/day ≥5 min apart; Android AppWidget ≥30 min); the only hands-off glance is a future Android foreground-service notification (Phase 3). Reversibility is near-nil: the auth/poll/format core is portable plain Dart, reusable toward a desk menu-bar companion later.

Plan-001 is the Live-Speed MVP. One screen: lazy-auth → poll GET /api/network/speed every 1s → render Download (rx) / Upload (tx) in Mbps, with LOADING, ERROR (keep last-known + a “stale” badge, never show 0 / crash), and RECONNECT (any 401 → transparent re-login + retry) states. No signal / battery / clients, no charts, no notification (those are Phase 2+ in docs/ future plans). Goal: a working, installable app on the user’s phone that shows true live up/down whenever the phone is on the modem’s WiFi.

Agent contract (verified against agent source — the spec, do not guess):

  • Base http://192.168.0.1:9090, LAN-only, plain HTTP. The modem is the WiFi + 5G uplink.
  • POST /api/auth/login {"password"} → {ok:true,data:{token}}; then Authorization: Bearer <token> on every other call. Token TTL 1h, in-memory on the agent → modem reboot / restart / expiry silently invalidates it. Treat any 401 as “re-login transparently and retry”, never fatal.
  • No-password mode is real: an agent with no password set allows unauthenticated access. Client tries unauthenticated first, falls back to login on 401.
  • GET /api/network/speed → {ok:true,data:{rx_bytes,tx_bytes,rx_speed,tx_speed,elapsed_ms}}. rx_speed/tx_speed are bytes/sec (f64), a rolling ~1s average of rmnet_data0 computed on-device. rx = download, tx = upload. Display ×8/1e6 for Mbps. Superseded by plan-008 ADR-0015: this ~1s / single-interface description was the belief at plan-001 time and is preserved here as the historical record, but it is wrong — the agent’s own mean spans ~15 s (16-slot ring, 15 intervals) and sums two interfaces (rmnet_data0 + rmnet_ipa0). See docs/adr/0015-derived-live-speed.md and the current CLAUDE.md §Agent contract for the corrected contract.
  • No CORS + plain HTTP → browser-origin pages are double-blocked; native Flutter HTTP is unaffected.

See CLAUDE.md for the full project contract + local-dev quirks. Security posture: never WAN-expose the agent (it has factory-reset endpoints); the user password lives in flutter_secure_storage, never committed; bearer tokens never logged.

Stack

Layer Tech Notes
App Flutter + Dart one codebase → Android + iOS
HTTP package:http thin; native client (no CORS constraint)
Secret storage flutter_secure_storage Keychain (iOS) / Keystore (Android) for the agent password
State plain Stream + StatefulWidget / ValueNotifier no heavy state lib at MVP; revisit if Phase 2 grows
Time (tests) package:fake_async + package:clock deterministic 1s-poll tests, no real waiting
Test fake Dart HttpServer in-process stub unit + integration without a real modem; CI-safe

Architecture rule: the auth + poll + parse + format logic lives in lib/core/ as pure Dart (zero flutter/material imports) so it is fast-unit-testable and extractable to a package later (toward a desk menu-bar companion). UI lives in lib/ui/; wiring in lib/app.dart. Justification: research §“hybridOption” (one core, multiple surfaces) — reversibility is the whole point.

Cleartext platform config (mandatory or every request fails): Android network-security-config permitting cleartext for 192.168.0.1 only; iOS NSAllowsLocalNetworking (scoped — never a blanket NSAllowsArbitraryLoads).

TDD cycle format

See .claude/rules/cycle-orchestration.md (paired with .claude/rules/tdd.md + .claude/rules/commit.md). Reviewer separation, architect gate, NO-DEFER, subagent prompt skeleton, reviewer hallucination guard — all unchanged. Architecture-review value on every cycle is mandatory (missing field → STOP). Security-tier cycles force the architect tier to opus and add the security-reviewer second pass regardless of the per-cycle field.

CYCLE X.Y — [behaviour name]
RED      (Model - Agent):          exact failing test assertions
GREEN    (Model - Agent):          minimal code to pass
REVIEW   (Model - code-reviewer):  issues list; never writes code
REFACTOR (Model - Agent):          domain expert applies review feedback

Model rules (tier→model binding in .claude/rules/lifecycle.md §Model tier map; REVIEW verdict floor is sonnet — never haiku):

Test complexity RED GREEN REVIEW REFACTOR
Simple structural (pure fn, DTO parse) haiku sonnet sonnet sonnet
Behavioural (stream, UI state machine) sonnet sonnet sonnet sonnet
Security / architecture tier opus (architect) sonnet sonnet (+ opus security-reviewer) sonnet

Agent roles:

Agent Role
software-architect Architecture gates only — never RED/GREEN
flutter-expert Dart core + Flutter UI — RED, GREEN, REFACTOR
uiux-expert Speed-screen states + semantics co-design (Cycle 1.7)

code-reviewer REVIEW only — identifies issues, never writes code
security-reviewer Second-pass review on security-tier cycles (1.4, 1.6, 1.8)

Out of scope (plan-001)

  • Remote / away-from-modem access — security hazard (agent exposes factory-reset); needs a LAN relay. Never WAN-expose.
  • The 143-endpoint control surface (band/cell lock, SMS, router config) — open-u60-pro’s native apps already own that.
  • Live home-screen widget / lock-screen number — OS-infeasible for a true 1s feed. Hands-off glance, if ever wanted, is a Phase-3 Android foreground-service notification (accepted persistent-notification + battery cost).
  • Signal / battery / connected-clients / charts — Phase 2 (extends the same core; future plan).

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
