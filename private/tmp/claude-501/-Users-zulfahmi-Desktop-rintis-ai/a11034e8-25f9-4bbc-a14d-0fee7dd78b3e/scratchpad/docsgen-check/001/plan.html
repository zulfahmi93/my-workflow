App scaffold + scoped cleartext platform config

flutter-expert architect: required (top) Closes: new — the Flutter project + the network p…

Scope: flutter create an app targeting Android + iOS — applicationId / bundle id dev.zulfahmi.u60monitor, display name “U60 Monitor”. Establish the lib/core/ (pure Dart) vs lib/ui/ directory boundary with a placeholder U60MonitorApp that boots to a “U60 Monitor” scaffold. The architect locks “scoped, not blanket” so the insecure default never ships.

1.4

Agent client + lazy bearer auth (no-password fallback + transparent re-login)

flutter-expert architect: required (top) security tier Closes: new — the authenticated HTTP boundary the…

Security tier. Threat model required. Attacker / failure surface: a bearer token written to logs or crash reports; an infinite login loop hammering the agent on a wrong password; a stale token after the modem reboots silently failing the app; the password embedded in code or a fixture. Mitigations: token held in memory only and excluded from any log/toString; login() attempted at most ONCE per request (a 401 after a fresh login → surface AuthFailure, do not loop); no-password mode handled (unauthenticated call succeeds, no login attempted); password obtained only via an injected Future<String?> Function() provider (the secure store in 1.8), never a literal.

Scope: lib/core/agent_client.dart — AgentClient wrapping package:http with getJson(path) (and a postJson), base URL injected, an optional password provider. Implements: unauthenticated attempt → on 401, if a password is available, POST /api/auth/login, cache token, retry the original request once with Authorization: Bearer <token>; on a second 401 throw AuthFailure; on no-password-and-401 throw AuthRequired. All tests use the in-process Dart HttpServer fake — zero real network.

Architecture review. required (top) — auth state machine — try unauthenticated first (no-password mode), POST /api/auth/login on 401, cache token in memory, and on ANY subsequent 401 (1h TTL / modem reboot) re-login ONCE and retry; bounded retry (no infinite loop on bad password); token never logged; password supplied via an injected provider, never hardcoded

RED
GREENminimal `AgentClient` over `package:http`; in-memory token; once-only login retry; `FakeAgent` HttpServer stub
REVIEW`sonnet` — `code-reviewer`
REFACTOR`sonnet` — `flutter-expert`
SECURITY-REVIEW`opus` — `security-reviewer` (token handling, retry-loop bound, no-secret-in-logs)
1.6

Credential + base-URL store (secure storage)

flutter-expert architect: required (top) security tier Closes: new — the secret store the wire-up (1.8)…

Security tier. Threat model required. Surface: the agent password persisted in plaintext (SharedPreferences / a file) and read off a rooted/backed-up device; the secret surviving an uninstall via cloud backup; the secret logged. Mitigations: persist ONLY via flutter_secure_storage (iOS Keychain first_unlock accessibility, Android EncryptedSharedPreferences/Keystore); never log the value; clear() removes it. null/absent password is a valid state (no-password mode), not an error.

Scope: lib/data/credential_store.dart — CredentialStore over an injected FlutterSecureStorage (faked in tests). API: Future<void> savePassword(String), Future<String?> password() (null when unset), Future<void> clear(), plus baseUrl() returning the stored override or the default http://192.168.0.1:9090. The password() getter is exactly the provider AgentClient (1.4) expects.

Architecture review. required (top) — agent password is a secret — must live in flutter_secure_storage (Keychain/Keystore), never SharedPreferences/plaintext; null = no-password mode (not an error); base URL default + override; clear() wipes the secret

RED
GREENthin wrapper over `flutter_secure_storage`; injectable for tests; default base URL constant
REVIEW`sonnet` — `code-reviewer`
REFACTOR`sonnet` — `flutter-expert`

1.5

SpeedPoller — 1s reading stream with stale + reconnect

flutter-expert architect: required (mid) Closes: new — the data stream the speed screen (1…

Scope: lib/core/speed_poller.dart — SpeedPoller taking an AgentClient + interval + (injected) clock. Exposes a Stream<SpeedReading> where SpeedReading{ snapshot: SpeedSnapshot?, isStale: bool, error: Object? }. Behaviour: every interval, GET /api/network/speed → parse via SpeedSnapshot.fromAgentJson → emit SpeedReading(snapshot, isStale:false). On any fetch/parse error, emit SpeedReading(last snapshot, isStale:true, error) — keep the last-known value, never emit 0, never close the stream on a transient error. dispose()/cancel stops the timer; no emissions afterward. Tested deterministically with fake_async + clock — no real waiting.

Architecture review. required (mid) — stream/timer lifecycle — emit a SpeedReading each tick over an injected clock; on fetch error keep last-known + isStale=true (never emit a fake 0 / never crash the stream); a 401 is handled inside AgentClient (1.4) so the poller just sees success/failure; dispose cancels the timer with no further emissions; single-subscription vs broadcast

RED
GREEN`Timer.periodic` over injected clock; last-known cache; `SpeedReading` value type; no real delays in tests
REVIEW`sonnet` — `code-reviewer`
REFACTOR`sonnet` — `flutter-expert`
1.7

Live speed screen (Download / Upload + loading / stale states)

flutter-expert + uiux-expert architect: required (mid) Closes: new — the one screen the MVP ships

Scope (UI cycle — (app)): lib/ui/speed_screen.dart — a SpeedScreen consuming a Stream<SpeedReading>. Renders a Download card (rx) and an Upload card (tx), each via formatRate (1.2). Manual smoke on a device/emulator per the GREEN UI gate.

Architecture review. required (mid) — screen state machine — bind a SpeedReading stream to Download/Upload cards; render LOADING (first frame, no snapshot yet), VALUE, and STALE (last-known + a visible stale badge, never 0); accessibility semantics for both readings; no business logic in the widget (formatting via lib/core/format.dart)

1.8

End-to-end wire-up — first-run auth + live screen on device

flutter-expert + test-engineer architect: required (top) security tier Closes: new — the composed app; install on the ph…

Security tier. Threat model required. Surface: the wire-up could log the password while passing it from store → client; an AuthFailure could loop the password prompt and hammer the agent; the password could be requested before the no-password path is tried (annoying + leaks that a password exists). Mitigations: the password flows only via the injected provider closure (never logged); on AuthRequired/AuthFailure the UI prompts once, stores via CredentialStore, and retries — bounded, no auto-loop; unauthenticated is always attempted first.

Scope: lib/app.dart composition — build AgentClient with passwordProvider: credentialStore.password, feed it to SpeedPoller, render SpeedScreen on its stream. First-run/empty-credential UX: a minimal password sheet shown only on AuthRequired/AuthFailure, saving to CredentialStore, then retrying. integration_test/ drives the full app against an in-process FakeAgent covering: (1) no-password agent streams immediately; (2) password agent prompts once → logs in → streams; (3) mid-session token wipe (reboot) → transparent reconnect, screen never blanks to 0; (4) unreachable agent → error/stale surface, last-known retained. Then a manual install on the real phone against the real modem.

Architecture review. required (top) — composition of the auth boundary with the secret store + a first-run password-entry UX — the credential flows from CredentialStore (1.6) into the AgentClient (1.4) provider; a 401 with no stored password prompts ONCE; on AuthFailure the prompt re-opens (wrong password) without looping the agent; integration proven against an in-process fake agent across no-password / password / mid-session-reboot / unreachable

RED
GREENcompose store→client→poller→screen in `lib/app.dart`; `PasswordSheet` on AuthRequired/AuthFailure; `integration_test` against `FakeAgent`
REVIEW`sonnet` — `code-reviewer`
REFACTOR`sonnet` — `flutter-expert`
SECURITY-REVIEW`opus` — `security-reviewer` (credential flow, no password in logs, bounded prompt retry)
