8 cycles, 5 batches. The win is B02 (four disjoint core sessions in parallel); the rest is a short linear chain (scaffold → core → poller → screen → wire-up). Each cycle is one fresh-context session per .claude/rules/cycle-orchestration.md §Session protocol; commit one cycle at a time after the human reviews the diff.

How to use

Run B01 alone (it creates the project). Then fan out B02’s four sessions (1.2, 1.3, 1.4, 1.6) — disjoint files, no shared edits except the already-frozen pubspec.yaml. Merge, then run 1.5 → 1.7 → 1.8 in sequence. Security-tier cycles (1.4, 1.6, 1.8) require BOTH code-reviewer and security-reviewer APPROVED before commit.

Common contract (applies to every session)

Every session: fresh context; read root /CLAUDE.md + projects/personal/u60-monitor/CLAUDE.md + the rules + this plan’s cycle entry; honour the architect-gate field; reviewer separation (never self-review); NO-DEFER on BLOCKER/REFACTOR; caveman tone is chat-only (code/tests/commits are idiomatic; security commit bodies explain the threat).

Worktree convention

Optional but recommended for the B02 parallel sessions: one git worktree per cycle (.worktrees/u60-monitor-1.<n> on branch cycle/1.<n>) so the four core sessions never touch each other’s tree. The linear cycles (1.1, 1.5, 1.7, 1.8) can run in the main tree.

Conflict notes from source

Stop conditions (across all batches)

Halt + write docs/AUTONOMOUS_RUN_STATUS.md on: architect NO-GO; a missing architect-gate field; a security-tier cycle whose gate isn’t top-tier; a BLOCKER/REFACTOR needing genuine deferral; REVIEW still NEEDS FIX after 3 REFACTOR passes; the test gate unreachable for reasons outside the cycle; a pre-commit hook failure; a cycle demanding out-of-bounds changes (a new dep, a second screen).

Final state

plan-001 done = an installable Flutter app (Android + iOS) that, on the modem’s WiFi, shows live Download/Upload in Mbps updating each second, survives modem reboot (transparent re-login), keeps last-known + a stale badge when the link drops, and stores the agent password in the platform keystore. Phase 2 (signal/battery/clients/charts) extends the same lib/core in a future plan.
