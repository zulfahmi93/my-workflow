9.1

Rewrite the project guide as AGENTS.md

technical-writer architect: none no TDD cycles

The highest-value item in the backlog. CLAUDE.md has exactly one commit (ca360f4, 2026-06-26 — verified via git log --oneline -- CLAUDE.md) and has drifted through 77 commits, 6 plans and 14 ADRs. It is the project’s ONLY local guide, so per the root AGENTS.md context-loading rule it is read FIRST by every agent entering this subtree; each inaccuracy is injected into every subsequent cycle.

Rewrite it as AGENTS.md against §What the rewritten guide must contain — that section is the specification for this cycle, read it in full. This is a rewrite against current reality, not a diff of the old file: preserve what is still true, delete what cannot be verified, and add the four things that are simply missing (Privacy section, lib/data/ in both the layer map and the commit scopes, the minimum upstream agent commit, and the .env note).

PRESERVE plan-008 cycle 8.1’s corrected speed-contract text VERBATIM (§plan-008 coordination). Do not re-derive the speed paragraph from the old version. Silently reverting that is the single worst outcome available to this cycle, and it would be invisible — the rewritten guide would read as coherent and confident while restating a claim already proven false.

NOT security-tier — no code, no auth surface; documenting the dormant ADR-0002 invariant does not discharge it.

9.6

Structural IntrinsicHeight assertion — the mechanical half of the ADR-0010 guard

flutter-expert architect: none

The mechanical half of 9.5’s second guard gap, and the only non-docs cycle in this plan.

ADR-0010:92-98 constrains the sticky-footer layout’s nested IntrinsicHeight structure — the mechanism that keeps the glance screen filling exactly one viewport without spuriously scrolling. Today nothing checks it: a refactor that adds or drops an IntrinsicHeight would pass the entire suite while breaking an architect-locked layout invariant that plans 002 through 008 all re-derive in prose.

Add a structural assertion to the integrated screen test — the backlog suggests expect(find.byType(IntrinsicHeight), findsNWidgets(3)).

Verify the actual count from the widget tree before asserting it; do not take 3 on faith. The count is the point of the test, and asserting a number copied from a backlog document would encode a guess as an invariant. Read speed_screen.dart and pump the tree.

RED must fail for the right reason: assert the verified count, confirm the test currently passes, then confirm it FAILS when an IntrinsicHeight is added or removed. A structural assertion that cannot fail is worse than no assertion — it reads as coverage while guarding nothing. If it cannot be made to fail meaningfully, say so and escalate rather than committing a tautology.

Reference ADR-0010 in the test’s comment so a future reader hitting the failure knows which invariant they broke and why it is load-bearing.

Architecture review. none — Adds one structural assertion to an existing widget test. No production line changes; ADR-0010’s constraint is unchanged and merely becomes machine-checked rather than prose-enforced. Standard TDD cycle gated by an opus code-reviewer pass. NOT security-tier.
