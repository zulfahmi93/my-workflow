plan-009 makes the written record match the code. Its scope is exactly the documentation items of docs/open-issues-2026-07-19.md, a backlog of 44 items that each survived an adversarial verification pass. Six cycles, none security-tier, ZERO code behaviour change. The centrepiece is the project guide, which has never been edited since 2026-06-26 and — being the only local guide — is read first by every agent entering this subtree, so its 11 defects propagate into every cycle that follows.

How to use

PREREQUISITE: plan-008 cycle 8.1 must have landed. Not a preference — see §plan-008 coordination. If it has not, STOP.

Sequencing. Run SEQUENTIALLY on main, one commit per cycle: 9.1 (guide → AGENTS.md) → 9.2 (dead-path sweep) → 9.3 (ADR accuracy) → 9.4 (README) → 9.5 (review-checklist, ROOT repo) → 9.6 (IntrinsicHeight guard).

9.2, 9.4, 9.5 and 9.6 are genuinely file-disjoint from 9.1/9.3 and from each other, so four of six could parallelize in worktrees. They do not, for two carried reasons: each cycle’s gate runs the whole flutter test suite, which is cross-attributable in a shared tree (the plan-004/005/006 lesson); and the nested repo’s worktrees must be managed MANUALLY, because the harness isolation:worktree yields an app-less ROOT worktree (/projects/ is gitignored at the monorepo root).

9.5 commits in the ROOT repo, every other cycle in the nested one. No cycle spans both — that isolation is deliberate. 9.5’s plan-status bump and cycle note are a separate nested-repo commit.

Commit scopes: docs (9.1 as docs(agents), 9.2 as docs(plan), 9.3 as docs(adr), 9.4 plain docs, 9.5 as docs(rules)), test (9.6).

Common contract (applies to every session)

Architect gate: none on every cycle. No architecture is decided here — the ADRs are being made to describe decisions already taken and shipped. A genuine substantive divergence between a recorded decision and the code is a STOP, not a docs fix, precisely because that would be an architecture question.

MODEL-TIER POLICY: ALL REVIEW on opus; GREEN/REFACTOR/RED default sonnet; never haiku.

The REVIEW pass is a FACT-CHECK, and it is this plan’s only real gate. Five of six cycles have no test. For every claim written or retained, the reviewer resolves it against actual source — a lib/** line, an agent Rust line, a git commit, an ADR — and any claim it cannot confirm is a BLOCKER, not a NIT. A docs cycle that transcribes the backlog on faith has laundered an unverified assertion into a more authoritative file: strictly worse than leaving the file stale. See §The verification standard.

Workflow execution. 9.6 runs via .claude/workflows/tdd-cycle.js ({ project: "u60-monitor", projectPath: "projects/personal/u60-monitor", plan: "009", cycle: "9.6", greenAgent: "Flutter Expert", redAgent: "Flutter Expert", securityTier: false }). 9.1–9.5 are no-tdd and run GREEN → REVIEW directly with a technical-writer and a fresh opus code-reviewer. Commits stay OUTSIDE the workflow.

Worktree convention

Not applicable — cycles run sequentially on main. (Harness note, carried from plan-004/007/008: isolation:worktree creates an app-less ROOT-repo worktree because /projects/ is gitignored at the monorepo root — the nested u60-monitor repo’s worktrees must be managed MANUALLY. Sequential-on-main sidesteps this entirely.)

Inter-batch verification

After each cycle: flutter test at its expected count (unchanged for 9.1–9.5; +1 for 9.6) + flutter analyze clean + a fresh code-reviewer (opus) APPROVED; update the cycle status: in plan-009.yaml; file docs/cycles/9.X.yaml (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). One commit per cycle per commit.md.

Three checks specific to this plan:

  • git diff lib/ must be empty for every cycle including 9.6. This plan is zero-behaviour-change by construction; a lib/ diff means scope leaked.
  • After 9.1 and 9.3, grep the corrected claim across docs/ and the guide — no doc may contradict another on the same fact. Fixing one file while leaving its contradiction in a sibling is the failure mode this plan exists to end.
  • After 9.2, grep -c '\.claude/rules' docs/plan-*.yaml returns 0 for all seven, and the legitimate .claude/workflows|skills|agents|settings.json references still resolve.

Stop conditions (across all batches)

  • plan-008 cycle 8.1 has not landed → STOP. Running 9.1 first either writes the speed contract twice with different numbers or silently reverts 8.1’s correction — and the revert is invisible, because the rewritten guide would read as coherent while restating a claim already proven false.
  • 9.1 re-derives the speed-contract paragraph from the old version rather than preserving 8.1’s text → BLOCKER.
  • A claim is written that the reviewer cannot trace to a source line, commit or ADR → BLOCKER. Delete the claim; do not soften it.
  • 9.3 finds a genuine SUBSTANTIVE divergence between an ADR’s recorded decision and the code (not stale wording) → STOP and escalate; that is an architecture question.
  • 9.3 touches ADR-0013 table (b), ADR-0003, or ADR-0015 (all plan-008 8.1’s) → BLOCKER.
  • 9.3 attempts the ADR-0014 forward-lock reconciliation → BLOCKER; that is plan-010, and it has code attached.
  • A bucket-(e) disposition cites no decision source, or A24 / E10 get dispositioned rather than moved to §Open questions → BLOCKER. Writing “accepted” without a citation is deciding on the owner’s behalf under cover of a docs cycle.
  • A bucket-(e) item turns out never to have been genuinely decided → STOP and escalate; it is open work, not a disposition.
  • 9.2 performs a blanket .claude/ → .agents/ substitution, breaking .claude/workflows|skills|agents|settings.json → BLOCKER.
  • 9.5’s diff contains a nested-repo file, or edits monitor_header.dart → BLOCKER. The design call on that instance is the owner’s.
  • 9.6’s assertion cannot be made to fail when an IntrinsicHeight is added or removed → STOP; do not commit a tautology.
  • Any lib/ production line changes in any cycle → STOP; out of bounds.
  • A second drifting guide is created (both AGENTS.md and a full CLAUDE.md) → BLOCKER; that is the defect this plan removes.
  • Any dependencies: add (none planned) → out-of-bounds STOP.
