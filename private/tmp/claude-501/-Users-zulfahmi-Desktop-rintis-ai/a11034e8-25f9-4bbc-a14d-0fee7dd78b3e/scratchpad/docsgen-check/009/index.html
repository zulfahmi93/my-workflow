Context

This plan executes the documentation slice of a verified backlog. docs/open-issues-2026-07-19.md is the output of an exhaustive sweep of every plan, cycle note, ADR, source marker and guide at HEAD 1ef8038 — 181 candidates, each put through an adversarial refutation pass, 138 surviving, deduped to 44 items. This plan takes items A10, A11, A12, A21, A22 and the .claude/rules/ path rot. Everything else in that document belongs to plan-010, plan-011, a later housekeeping plan, or the root monorepo (§Out of scope).

The backlog is reference, not authority. Its citations are file:line at HEAD 1ef8038 and it is explicitly marked as a point-in-time snapshot. Every cycle here MUST re-verify each claim against current source before writing a fix. For a docs plan that verification is the work — a docs cycle that transcribes the backlog on faith has done nothing except move an unverified assertion into a more authoritative file.

Why the guide is the highest-value target in the whole backlog. Root AGENTS.md says: “When operating inside a nested project, also follow the nearest project-local guide,” and u60-monitor has exactly one — CLAUDE.md, with no AGENTS.md. So it is loaded first by every agent entering this subtree, and every inaccuracy in it is an inaccuracy injected into every subsequent cycle. Verified: git log --oneline -- CLAUDE.md returns exactly one commit.

The 11 defects (§D1 of the backlog) are not typos. A representative sample:

  • :3 points at .claude/rules/. Verified: that directory does not exist; the canonical rules moved to .agents/rules/ in root commit 88949bb. An agent told to read .claude/rules/tdd.md finds nothing.
  • :12-23 is headed “Agent contract (verified against agent source — do not guess)” and documents 2 of 7 endpoints. This is worse than an omission: upstream exposes BOTH /api/battery (server.rs:125) and the /api/device/charge-control the app actually uses (:148), so an agent that trusts the heading and guesses the rest picks the wrong one.
  • :10 omits lib/data/ from the layer map — the one component that holds the modem password, and the one deliberate exception to the pure-Dart lib/core rule. :46-50 likewise has no commit scope covering it, which has already produced one mis-scoped commit (3a41349, shipped as feat(core) with only lib/data/ source).
  • :35 describes a fake-agent approach that ADR-0002:51-54 records as REJECTED. A contributor following the guide rediscovers a known dead end.
  • No Privacy section at all. The no-PII stance exists only as a comment in clients_snapshot.dart:8-10.

The path rot is not confined to the guide. Verified by count: 74 occurrences of .claude/rules across the seven plan YAMLs (plan-001: 11, plan-002: 18, plan-003: 8, plan-004: 12, plan-005: 6, plan-006: 5, plan-007: 12; plan-008: 0). Many sit inside subagent “Mandatory reads” blocks — plan-002.yaml:255,379 among them — so a cycle re-run from those plans instructs its agents to read files that cannot resolve. Mechanical to fix, load-bearing for every future run.

Five ADRs assert things the code contradicts. Two spot-verified while authoring this plan: ADR-0013:65-70 still reads “Advisory (not a regression, no action this cycle) … A timeout is a possible future hardening” — but the timeout shipped in cycle 6.3 and is live at agent_client.dart:196 (await provider().timeout(_timeout)) with two tests; and ADR-0005:37,42 still calls collapsing SpeedPoller onto Poller<SpeedSnapshot> “a tracked follow-up,” which cycle 3.1 completed by deleting the file. ADRs 0003/0004/0006/0007 all link into ADR-0005, so readers are actively routed into stale text.

Two guard gaps where an ADR rule is enforced only by prose — and one is already being violated. ADR-0008:76-77 forbids placing muted and faint text adjacent at the same size, but the only guard (refinement_theme_test.dart:541-561) checks contrast ordering, not adjacency — and the forbidden pattern is live at monitor_header.dart:158-172 (muted title glyphs + a faint / separator, both fontSize: 11.0, same Row), landed after the ADR. Whether that specific instance is a real legibility defect or intentional decorative chrome is a design call for the owner and is NOT decided here; what this plan fixes is that nothing would have caught it. ADR-0010:92-98’s nested-IntrinsicHeight constraint is likewise re-derived by prose in each plan; grep -rni intrinsic .agents/ returns zero hits.

ZERO code behaviour change. The single non-doc artifact in this plan is 9.6’s structural test, which adds an assertion and changes no production line.

TDD cycle format

See .agents/rules/cycle-orchestration.md (paired with tdd.md + commit.md). Reviewer separation, architect gate, NO-DEFER, reviewer hallucination guard — unchanged. Architecture-review value on every cycle is mandatory (missing field → STOP).

Five of six cycles are no-tdd — there is no failing test to write for a prose correction. They are NOT therefore ungated:

CYCLE 9.X — [docs artifact]
GREEN    (sonnet - technical-writer):  author / correct the prose
REVIEW   (opus  - code-reviewer):      VERIFY EVERY CLAIM AGAINST SOURCE
REFACTOR (sonnet - technical-writer):  apply review findings

The REVIEW pass IS the gate for this plan, and its job is unusual: it is a fact-check, not a style read. For every factual assertion the cycle writes or leaves standing, the reviewer must resolve it against actual source — the Dart file, the agent’s Rust file, the git log — and reject any claim it could not confirm. A docs cycle that transcribes the backlog on faith has laundered an unverified assertion into a more authoritative file, which is strictly worse than leaving the file stale. Findings are tagged BLOCKER / REFACTOR / NIT per tdd.md; an unverifiable claim is a BLOCKER.

9.6 is a normal RED → GREEN → REVIEW cycle.

Model rules (standing project directive — overrides the default tier map: architect gates + ALL REVIEW use opus; RED/GREEN/REFACTOR default sonnet; never haiku):

Cycle kind RED GREEN REVIEW REFACTOR
Docs (9.1–9.5) — sonnet opus sonnet
Structural test (9.6) sonnet sonnet opus sonnet

Agent roles:

Agent Role
technical-writer GREEN + REFACTOR on 9.1–9.5
flutter-expert RED + GREEN + REFACTOR on 9.6
code-reviewer REVIEW only (opus) — fact-checks against source, never writes

No architect gate on any cycle — no architecture is being decided; the ADRs are being made to describe decisions already taken and shipped. Where a cycle discovers that an ADR’s recorded decision and the code genuinely diverge on substance (not wording), that is a STOP condition, not a docs fix (§Stop conditions).

The verification standard (what "done" means for a docs cycle)

A prose fix has no test. The substitute discipline for every cycle in this plan:

  1. Nothing is transcribed. Each claim written or retained must be traced to a specific artifact — lib/** line, ~/Desktop/tools/open-u60-pro/zte-agent/src/** line, a git commit, or an ADR. If it cannot be traced, it does not go in the file.
  2. The backlog is a lead, not a source. docs/open-issues-2026-07-19.md cites file:line at HEAD 1ef8038. Open the file. Line numbers drift; two of its claims were already spot-verified during plan authoring and both held, but that is evidence about the sweep’s quality, not a licence to skip the check.
  3. Prefer deleting a claim to guessing at it. An accurate short guide beats a comprehensive one with three plausible inventions. The endpoint section is the live example: it is wrong because it over-claims under a heading that says “do not guess.”
  4. REVIEW rejects unverifiable claims as BLOCKER, not NIT. See §tdd-cycle-format.
  5. Cross-file consistency. After 9.1 and 9.3, no doc may contradict another on the same fact. The reviewer greps for the corrected claim across docs/ and the guide.

What the rewritten guide must contain (9.1)

Not a diff of the old file — a rewrite against current reality, preserving what is still true. Minimum contents:

  • What it is + stack. Six pollers, six screen sections. The current :3 (“showing live upload/download speed”) and pubspec.yaml:2 both describe the plan-001 app.
  • Layer map including lib/data/ — the modem password lives there (credential_store.dart), and it is the deliberate exception to the pure-Dart lib/core boundary. Name that explicitly; the boundary is a review BLOCKER rule and its one exception must be as visible as the rule.
  • Agent contract, honestly scoped. Either document all seven endpoints the app uses, or say plainly which are documented and that the rest must be read from ~/Desktop/tools/open-u60-pro/zte-agent/src/. Call out the /api/battery vs /api/device/charge-control trap by name. Preserve plan-008 8.1’s speed-contract text verbatim (§plan-008 coordination).
  • A minimum upstream agent commit (A21). The 10 s data-usage cadence is only safe because upstream 0f8e6ae batched the uci reads into one uci show. Nothing pins that, and poller.dart has no re-entrancy guard — so against a pre-0f8e6ae agent the app issues stacked overlapping requests rather than backing off. State the minimum commit and the consequence of running older.
  • Rate + unit rules, current. The ×8/1e6 note predates the four-tier adaptive ladder (format.dart:47-62) with its em-dash sentinel. Byte volumes are binary IEC — an intentional, user-visible divergence from the modem’s own UI, currently recorded only in ADR-0011.
  • Freshness model. The flat three-state rule predates ADR-0009’s per-tile independent freshness (no global overlay). Note: FreshnessState is a 3-value enum; the “five states” phrasing in some notes conflates it with AsyncSnapshot cases — do not propagate that.
  • Testing approach that matches reality. App-level tests use fake_multi_client.dart. The HttpServer stub described at :35 is the approach ADR-0002:51-54 rejected; real-socket coverage lives at the AgentClient layer (fake_agent.dart), and app_multipoller_test.dart:22-23 documents why widget tests cannot use a loopback server.
  • A Privacy section. Currently absent. The no-PII stance lives only in clients_snapshot.dart:8-10.
  • Commit scopes covering lib/data/.
  • Correct rules path — .agents/rules/.
  • Local-dev quirks: mention .env (plaintext ROUTER_PASS/AGENT_PASS, correctly gitignored, currently read by nothing).
  • Replace the “143-endpoint control surface” line. Verified wrong (149 arms / 127 paths) and the app does read into it. The invariant that actually holds, and is stated nowhere: zero state-changing calls — one _client.get at agent_client.dart:145 plus the login POST at :210.

Migration: author as AGENTS.md per root AGENTS.md (“Prefer AGENTS.md; honor a legacy CLAUDE.md when that is the only local guide”). Check .claude/ conventions first; if the Claude adapter needs a CLAUDE.md to exist, leave a one-line pointer file rather than a second copy — two guides that can drift is the defect this plan exists to remove.

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
