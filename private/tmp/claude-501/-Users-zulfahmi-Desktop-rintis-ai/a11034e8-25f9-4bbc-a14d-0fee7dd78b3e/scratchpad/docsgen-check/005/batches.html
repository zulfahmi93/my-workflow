plan-005 mirrors the modem’s data-management (usage + plan + reset-day) as a READ-ONLY editorial section in 5 file-disjoint cycles across 3 batches. The architect gate is consolidated on 5.1; 5.4/5.5 defer. No cycle is security-tier. Every UI cycle (5.4/5.5) requires the frontend-design:frontend-design skill. ZERO new pubspec deps. One EXTERNAL prerequisite: the open-u60-pro /api/data-usage plan-block extension (§Agent change).

How to use

Sequencing. P5.A {5.1 model (opus gate, files ADR-0011+0012) ‖ 5.2 formatBytes ‖ 5.3 status math} — pure-Dart, file-disjoint (data_usage_snapshot.dart + core.dart ‖ format.dart ‖ data_usage_status.dart). → P5.B {5.4 section widget, read-only}. → P5.C {5.5 integration}. One commit per cycle per commit.md; scopes: core (5.1/5.2/5.3), app (5.4/5.5). The agent change ships in open-u60-pro on its own (not a cycle here).

Common contract (applies to every session)

Architect gate. ONE foundational opus gate on 5.1 → GO/NO-GO locking ALL cross-cutting decisions (incl. the agent-endpoint read-only contract); files ADR-0011 + ADR-0012. 5.4/5.5 set arch-review deferred to 5.1 and read docs/cycles/5.1.yaml architect-verdict before RED. 5.2/5.3 are none. MODEL-TIER POLICY: architect gate + ALL REVIEW on opus; RED/GREEN/REFACTOR default sonnet; never haiku. NOT security-tier → no security-reviewer second pass.

frontend-design mandate (UI cycles). 5.4, 5.5 each REQUIRE the implementer to invoke frontend-design:frontend-design BEFORE writing widget/layout code — wired into each session.prompt. REVIEW MUST confirm it; a UI cycle that skipped it is NEEDS FIX.

Worktree convention

For the parallel P5.A cycles, run each in its OWN git worktree OR serialise the flutter analyze / flutter test runs — whole-project analyze/test are cross-attributable. (Harness note: isolation:worktree creates an app-less ROOT-repo worktree because /projects is gitignored at the root — manage the nested u60-monitor repo’s worktrees MANUALLY, as in plan-004.)

Batch summary

Batch Sessions Wall-time hint Notes
P5.A 5.1 ‖ 5.2 ‖ 5.3 100–160 min Foundations, parallel, file-disjoint. 5.1 = DataUsageSnapshot (usage + plan) model + the foundational opus architect gate that files ADR-0011 + ADR-0012 and locks the cross-cutting decisions (incl. the agent endpoint contract). 5.2 = formatBytes binary IEC, KiB/MiB/GiB/TiB labels (appends to format.dart). 5.3 = DataUsageStatus percent math. Files: data_usage_snapshot.dart + core.dart ‖ format.dart ‖ data_usage_status.dart — disjoint. 5.2/5.3 implement decisions PRE-LOCKED in this plan + ADR text; a 5.1 architect overturn of a byte-unit or status rule forces 5.2/5.3 rework — STOP. P5.B 5.4 70–110 min 5.4 = the new editorial DataUsageSection widget (UI; MUST use frontend-design) — deps 5.1/5.2/5.3. Read-only: renders used / plan / % / resets-day-N / reminder; NO SET-LIMIT affordance, NO edit. The limit bar activates the reserved red token at over-plan. Not security-tier.
P5.C 5.5 80–130 min 5.5 = the integration cycle (analogue of plan-002 Cycle 2.13): extend the data-usage poll parse to the new plan block, wire DataUsageSection into the screen ABOVE the Spacer with its own per-tile freshness, and re-gate no-scroll + 1.3× overflow. File-ownership forces app.dart + speed_screen.dart + the shared fakes into one cycle. UI cycle; MUST use frontend-design. Not security-tier.

Inter-batch verification

After each cycle: full flutter test green + flutter analyze clean + a fresh code-reviewer (opus) APPROVED; update the cycle status: in plan-005.yaml; file docs/cycles/5.X.yaml (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). The Flutter cycles use a FAKE stub of the extended /api/data-usage; the live agent is needed only for the deploy-pass.

Stop conditions (across all batches)

  • A 5.1 architect overturn of a byte-unit or status rule after 5.2/5.3 are built → STOP, rework.
  • Any dependencies: add (there is none planned) → out-of-bounds STOP.
  • Any base-URL setter, or any MODEM WRITE (e.g. set_wwandst_monthlimit) — that is the out-of-scope future write cycle and IS security-tier → STOP.
  • A UI cycle (5.4/5.5) where the implementer did not invoke frontend-design:frontend-design → REVIEW NEEDS FIX.

Final state

Test trajectory: baseline ~232 → roughly +14 (5.1) +12 (5.2) +10 (5.3) +18 (5.4) +12 (5.5) ≈ ~298 tests. The modem’s real used / plan / reset-day render as a read-only editorial section (e.g. 114.15 / 45 GiB · OVER 254% · resets day 5); over-plan activates the reserved red token; ADR-0011 + ADR-0012 filed; ADR-0002 dormant; ZERO new deps. The open-u60-pro /api/data-usage plan-block extension is the external prerequisite for the on-device deploy-pass. No git remote — never push.
