plan-008 makes the headline DL/UL number actually live. Today the app displays the agent’s rx_speed/tx_speed, a ~15-second rolling mean, so a burst takes ~15 s to register and ~15 s to decay. The fix derives the rate in-app from the cumulative rx_bytes/tx_bytes counters the app already parses and never uses — which requires oversampling the speed poll at 250 ms, because at 1 Hz the counter’s own quantization makes the elapsed tick count unrecoverable and the derived number aliases into a ±100% flap. Ten cycles, none security-tier, ZERO new pubspec deps. The pre-plan 4-design/4-judge architect verdict is the gate for the whole plan; no cycle re-gates.

How to use

Sequencing. Run SEQUENTIALLY on main, one commit per cycle: 8.1 (docs + ADRs) → 8.2 (deriver steady state) → 8.3 (defensive branches) → 8.4 (publish gating) → 8.5 (harness fidelity) → 8.6 (wiring) → 8.7 (cadence flip) → 8.8 (measured zero) → 8.9 (lifecycle pause) → 8.10 (human device pass).

Three ordering constraints are load-bearing, not stylistic:

  • 8.2 → 8.3 → 8.4 are the same file and strictly serial. Implementing a later cycle’s branches early makes that cycle’s RED unfailable — a REVIEW blocker, called out in each cycle’s prompt.
  • 8.5 before 8.6. With the harness advertising 1.25 MB/s against a frozen counter, a harness failure and a wiring failure are indistinguishable.
  • 8.6 before 8.7. Wiring lands with pollInterval still at 1 s, so the cadence flip is its own minimal, independently-revertable diff.

8.1 and 8.8 are genuinely file-disjoint from the deriver cycles and could parallelize in worktrees, but the run stays sequential on main because each cycle’s full-suite flutter test gate is cross-attributable in a shared tree (the plan-004/005/006 lesson). Commit scopes: docs (8.1), core (8.2, 8.3, 8.4), test (8.5), app (8.6, 8.8), perf/app (8.7, 8.9).

Common contract (applies to every session)

Architect gate: none on every cycle. The pre-plan 4-design/4-judge verdict (§Architect verdict) is the gate for this whole plan — it locked the file, class, constructor defaults, the 16-step guard order, both quantization rules, the cadence, the edge-case table and the blast radius, and it explicitly states “no further architect gates”. 8.7 amends architect-locked ADR-0013(b), but the ruling was made in the verdict and is transcribed by 8.1, so it does not re-gate. MODEL-TIER POLICY: ALL REVIEW on opus; RED/GREEN/REFACTOR default sonnet; never haiku.

No cycle is security-tier. Nothing touches auth, secrets, PII, crypto or an injection sink — the change consumes two integers already on the wire. 8.6 nonetheless carries a NAMED REVIEW MUST-CHECK: _checkAuthError must run on every raw reading, OUTSIDE the publish gate, or auth-halt recovery is delayed by up to a second. That is a preservation requirement, and the must-check exists to keep it preserved.

Workflow execution. Cycles run via .claude/workflows/tdd-cycle.js ({ project: "u60-monitor", projectPath: "projects/personal/u60-monitor", plan: "008", cycle, greenAgent: "Flutter Expert", redAgent: "Flutter Expert", securityTier: false }). The workflow returns a schema-validated record (RED/GREEN reports, review passes + adversarial verification); the orchestrator files the cycle note (reviewer-agent-id = wf:<runId>/review-pass-<N>), updates status:, regenerates docs, and commits. Commits stay OUTSIDE the workflow. 8.1 and 8.10 are no-tdd and do not use the workflow’s RED/GREEN path.

Worktree convention

Not applicable — cycles run sequentially on main, not in parallel worktrees. (Harness note, carried from plan-004/007: isolation:worktree creates an app-less ROOT-repo worktree because /projects is gitignored at the root — the nested u60-monitor repo’s worktrees must be managed MANUALLY. Sequential-on-main sidesteps this entirely.)

Inter-batch verification

After each cycle: full flutter test green + flutter analyze clean + zero flutter/material/dart:ui import under lib/core + a fresh code-reviewer (opus) APPROVED; update the cycle status: in plan-008.yaml; file docs/cycles/8.X.yaml (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). One commit per cycle per commit.md.

Two extra per-cycle checks specific to this plan:

  • git diff --stat lib/core/speed_history.dart lib/core/poller.dart lib/core/reading.dart must be empty for every cycle. These three files are untouched by the whole plan; a diff means derivation leaked into the generic poller or the ring, which is an instant BLOCKER.
  • After 8.7, confirm the PUBLISHED cadence is still ~1 Hz. If the ring starts filling at 4 Hz the publish gate has broken and ADR-0003’s 2-minute window is silently now 30 seconds.

Stop conditions (across all batches)

  • 8.2’s beat test cannot be made to pass across the full phase sweep → the design is falsified. STOP, return to the architect. Do NOT weaken the sweep, the 1% tolerance, or the naive control to get green — the control existing is the point.
  • The naive 1 Hz control in 8.2 passes (does not produce a ≤ 0.5·R and a ≥ 1.5·R sample) → the test harness is not actually reproducing the beat, so the real test proves nothing. STOP and fix the harness.
  • A later cycle’s guard branches implemented early (8.3’s branches in 8.2, or 8.4’s throttle in 8.3) → REVIEW BLOCKER; that cycle’s RED can no longer fail honestly.
  • _checkAuthError gated behind publish in 8.6 → BLOCKER, must be fixed before COMMIT.
  • An absurd/reset value clamped rather than re-seeded, or a wrap-correction added on decrease → BLOCKER. Both fabricate measurements.
  • splitRate modified in 8.8 (rather than adding the sibling helper) → BLOCKER; it silently changes the PEAK/empty-ring path.
  • More than ONE existing assertion breaking in 8.7 → STOP and investigate; the verified blast-radius analysis says only app_multipoller_test.dart:65 should change.
  • Any assertion edited in 8.5 → STOP; the counter increments are wrong.
  • A diff to lib/core/speed_history.dart, poller.dart or reading.dart in ANY cycle → BLOCKER.
  • Any dependencies: add (none planned) → out-of-bounds STOP.
  • 8.10 item 1 (battery) fails → apply/extend 8.9’s lifecycle pause; slowing the poll is NOT an acceptable remedy and requires returning to the architect.
  • 8.10 item 2 confirms IPA batch smoothing → the achievable win is capped at source; return to the architect for the 2-tick-window decision. Do not add machinery in the field.

Final state

Test trajectory: baseline 381 → roughly +12 (8.2) +10 (8.3) +5 (8.4) +2 (8.5) +4 (8.6) +2 (8.7) +5 (8.8) +4 (8.9) ≈ ~425 tests, with exactly ONE existing assertion changed (app_multipoller_test.dart:65, a cadence constant).

The headline DL/UL number responds in ~1 second instead of trailing a 15-second mean; the chart and PEAK sharpen with it (intentionally — PEAK becomes a true short-window peak instead of the max of a 15 s mean); a measured zero reads '0 bps' instead of flickering against '—'; the agent’s averages survive as a one-sample seed/fallback on five guarded paths so the worst observable behaviour is exactly today’s, for one sample. SpeedHistory, Poller<T> and Reading<T> are untouched. The false “~1s average of rmnet_data0” claim is gone from the project guide, and ADR-0015 records why the cadence is 250 ms so nobody optimises it back. ZERO new deps. No git remote — never push.

Remaining after plan-008: the human on-device pass (8.10) and its two possible escalations, plus the deliberately-deferred chart-axis-scaling question.
