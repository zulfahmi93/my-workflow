Context

plan-006 is a debt-closure plan, not a feature. After plan-005 shipped the read-only Data-Usage mirror and the post-plan-005 on-device fix round (Cycle A immediate-first-tick + tuned cadences + single-flight login; Cycle B 5G-NSA-vs-4G+ classification; Cycle C adaptive DL/UL speed unit; the open-u60-pro uci show wrapper batch), a full scout of every plan-001→005 open-questions + cycle-followups row plus the session-known ad-hoc items was run and each candidate verified against current source (HEAD 87d623c, 310/310 green).

Almost everything is already closed. The plan-004 optional-NIT burndown and the plan-003 supersessions cleared the backlog: the SpeedPoller→Poller<SpeedSnapshot> collapse is done (3.1 deleted speed_poller.dart); AgentClient.close() exists and is wired into _disposePollers with a double-close guard; the StatusStrip textContaining('3') NIT is moot (the widget was deleted in plan-004’s FooterTriplet redesign); FU-18 / 2.15 spacing / PEAK-8×-unit / every 4.x NIT are done or superseded. See §Fix inventory for the full closed list with evidence.

Three items survive as genuinely-open, actionable code/test work, each confirmed still-present in source:

  1. ecio decimal-parse (latent). lib/core/signal_snapshot.dart:144 still parses the WCDMA ecio (3G Ec/Io) field with the integer parseInt, while nr5g_snr / lte_snr were moved to the rounding parseDecimalInt in the Cycle-B network-classification fix. Firmware emits Ec/Io as a decimal string (e.g. "-8.5"); int.tryParse("-8.5") returns null → 3G signal quality is silently dropped. Untriggered on this device (LTE/5G), but a real latent bug and the last unfixed member of the decimal-string parse class. → Cycle 6.1 (core, non-security).

  2. PEAK label not adaptive. lib/ui/widgets/speed_history_chart.dart:105 hardcodes '${bytesPerSecToMbps(peak).round()} Mbps'. Cycle C made the DL/UL twin adaptive across the bit-rate ladder (bps/Kbps/Mbps/Gbps via splitRate) but the chart’s PEAK label was left as fixed Mbps → “PEAK 0 Mbps” at low throughput, inconsistent with the twin directly above it. → Cycle 6.2 (UI, non-security).

  3. Un-timeouted login secret read (ADR-0013 advisory). lib/core/agent_client.dart:182 does final password = await provider() with no timeout. The following _client.post(...).timeout(_timeout) IS bounded, but the secure-store read is not. Because the immediate-first-tick + single-flight guard (Cycle A) collapse all six pollers onto ONE shared _loginInFlight, a hung flutter_secure_storage read (device memory pressure, a corrupted Keychain/Keystore entry) stalls that single login and thus every section indefinitely on “Reconnecting…”. This touches the login/secret path → security-tier. The same cycle also closes the sec-A coverage gap: an explicit concurrent warm-token-expiry re-login regression test (existing tests cover single-caller expiry and cold-token concurrency, but not concurrent callers hitting a just-expired warm token). → Cycle 6.3 (core, SECURITY-TIER, opus architect gate).

A tiny doc-comment refresh (lib/core/core.dart’s “Contents (plan-001 through plan-003)” header omits plan-004/005/006) folds opportunistically into Cycle 6.1’s lib/core diff — optional, not a cycle of its own.

Everything else the scout surfaced is not actionable here: human-only on-device visual eyeballing, the optional upstream PR of the agent wrapper to jesther-ai, the dormant ADR-0002 base-URL-setter invariant, a future modem-write cycle, a precise client-count that needs an agent-side endpoint, and a repo-wide docs-gen cycle-note-schema change. All are recorded verbatim in §Cycle follow-ups.

Security-tier ruling

6.1 and 6.2 are NOT security-tier. 6.1 is a deterministic pure-function parse swap (integer→decimal parser) with no I/O, no auth surface, no injection sink — numeric string → int?. 6.2 is a presentation-only label-format change reusing an existing helper. Architect gate + ALL review on opus per the model-tier policy (a quality choice, not a security requirement); no security-reviewer second pass.

6.3 IS security-tier. It edits _performLogin (authentication logic) and the secure-store password read (secret material) — two items on the .claude/rules/cycle-orchestration.md §Security-tier list. The change is a liveness/availability hardening (bounding a read that could otherwise stall the shared login), not a new attacker vector, but the repo posture is that ANY edit to the login/secret-read path takes the second-pass security-reviewer (opus) + a top-tier architect gate. The architect must confirm: TimeoutException maps to AuthRequired/AgentError (never silent success), the not-async _login() single-sync-turn invariant (ADR-0013) is preserved, and _loginInFlight is cleared on the timeout path (the existing whenComplete already covers it). Threat model recorded in the 6.3 cycle note (attacker-can / mitigation-blocks / residual-risk).

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
