plan-006 closes the three genuinely-open follow-ups that survived the plan-001→005 scout + the post-plan-005 on-device fix round, as three small file-disjoint TDD cycles. 6.1 + 6.2 are non-security (no architect gate); 6.3 is security-tier (opus architect gate + security-reviewer second pass). ZERO new pubspec deps. Everything else in the backlog is closed, superseded, human-only, or a dormant invariant (§Fix inventory).

How to use

Sequencing. Run SEQUENTIALLY on main, one commit per cycle: 6.1 (ecio decimal-parse, core) → 6.2 (PEAK adaptive label, UI) → 6.3 (login secret-read timeout, security-tier, core). Although the three files are disjoint, the cycles are NOT parallelized: each cycle’s GREEN gate runs the whole flutter test suite, which is cross-attributable in a shared working tree (the plan-004/005 lesson). Commit scopes: core (6.1, 6.3), app (6.2).

Common contract (applies to every session)

Architect gate. 6.1 + 6.2 = none (pure-function / presentation-only; both reuse an existing, already-reviewed helper). 6.3 = required (opus) per §Security tier. MODEL-TIER POLICY: architect gate + ALL REVIEW on opus; RED/GREEN/REFACTOR default sonnet; never haiku. 6.3 additionally takes the security-reviewer (opus) second pass; both reviewers APPROVED before COMMIT.

Workflow execution. Cycles run via .claude/workflows/tdd-cycle.js ({ project: "u60-monitor", projectPath: "projects/personal/u60-monitor", plan: "006", cycle, greenAgent: "Flutter Expert", redAgent: "Flutter Expert", securityTier }). The workflow returns a schema-validated record (arch verdict, RED/GREEN reports, review passes + adversarial verification, security second pass); the orchestrator files the cycle note (reviewer-agent-id = wf:<runId>/review-pass-<N>), updates status:, regenerates docs, and commits. Commits stay OUTSIDE the workflow.

Worktree convention

Not applicable — the cycles run sequentially on main, not in parallel worktrees. (Harness note, carried: isolation:worktree creates an app-less ROOT-repo worktree because /projects is gitignored at the root — the nested u60-monitor repo’s worktrees must be managed MANUALLY. Sequential-on-main sidesteps this entirely.)

Inter-batch verification

After each cycle: full flutter test green + flutter analyze clean + a fresh code-reviewer (opus) APPROVED (+ security-reviewer APPROVED for 6.3); update the cycle status: in plan-006.yaml; file docs/cycles/6.X.yaml (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). One commit per cycle per commit.md.

Stop conditions (across all batches)

  • 6.3 architect returns NO-GO, or requires the _login() wrapper to become async (that would break the ADR-0013 single-sync-turn invariant) → STOP, escalate.
  • A 6.3 timeout mapping that could issue an unauthenticated request on the timeout path (silent success) → BLOCKER, must be fixed before COMMIT.
  • Any dependencies: add (none planned) → out-of-bounds STOP.
  • Any existing test weakened to fit a fix → STOP (these cycles only ADD tests).
  • A base-URL setter or a modem WRITE introduced (out of scope; the write path is a separate security-tier future cycle) → STOP.

Final state

Test trajectory: baseline 310 → roughly +3 (6.1) +4 (6.2) +3 (6.3) ≈ ~320 tests. The latent 3G Ec/Io decimal bug is fixed; the chart PEAK label is adaptive and consistent with the DL/UL twin; the login secret read is bounded so a hung read can no longer stall all six pollers, with a concurrent warm-expiry regression test closing the sec-A gap. ADR-0013 §Advisory discharged. ZERO new deps. No git remote — never push. Remaining after plan-006: only human-only on-device visual verification + the optional upstream agent-wrapper PR.
