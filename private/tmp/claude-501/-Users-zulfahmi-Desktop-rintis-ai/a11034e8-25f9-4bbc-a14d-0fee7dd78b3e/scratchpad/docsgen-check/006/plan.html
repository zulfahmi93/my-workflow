6.1

ecio decimal-parse — fix the latent 3G Ec/Io silent-null

flutter-expert architect: none

In lib/core/signal_snapshot.dart, the WCDMA ecio (3G Ec/Io) field is parsed with the integer parseInt (final ecio = parseInt(str('ecio'));), while nr5g_snr and lte_snr use the rounding parseDecimalInt (added in the Cycle-B network-classification fix). Firmware emits Ec/Io as a decimal string (e.g. "-8.5"); int.tryParse returns null → the value is silently dropped, so a 3G-connected device would show no signal quality. Swap ecio to parseDecimalInt (same sentinel/"0" handling, rounds to nearest int). Latent — this device is on LTE/5G — but a real bug and the last unfixed member of the decimal-string parse class.

The RED author MUST first read signal_snapshot.dart to confirm the exact field the parsed ecio flows into (sinrDb on the WCDMA branch) and the exact Dart rounding of a .5 decimal ((-8.5).round() ties away from zero), and write assertions against the verified path/values — not against this sketch.

Optional: refresh lib/core/core.dart’s “Contents (plan-001 through plan-003)” doc header to include plan-004/005/006 (a pure doc comment; only if core.dart is already open — do not add churn otherwise). Keep lib/core import-clean. All prior core tests stay green.

Architecture review. none — One-line parser swap (parseInt→parseDecimalInt) for the WCDMA ecio field, mirroring the already-reviewed Cycle-B decimal-string fix for nr5g_snr/lte_snr. Deterministic pure function, no I/O, no architecture surface, no new abstraction (parseDecimalInt already exists). Correctness gated by code-review. NOT security-tier (numeric parse, no auth/injection surface).

RED
GREENswap `final ecio = parseInt(str('ecio'))` to `parseDecimalInt(str('ecio'))` in lib/core/signal_snapshot.dart; keep sentinel/0 handling; update the ecio doc-comment to note decimal-string parsing (mirrors nr5g_snr/lte_snr); optional core.dart doc-header refresh; full suite green; lib/core import-clean

Rebuild the PEAK value string via splitRate(widget.peakBytesPerSec) so PEAK uses the same adaptive unit as the twin directly above it. 6.3

Login secret-read timeout + concurrent warm-expiry regression (security-tier)

flutter-expert architect: required (top) security tier Closes: plan-006 — the ADR-0013 §Advisory (un-tim…

In lib/core/agent_client.dart, _performLogin does final password = await provider(); (line ~182) with no timeout; the following _client.post(...).timeout(_timeout) IS bounded but the secure-store read is not. Because Cycle A’s immediate-first-tick + single-flight guard collapse all six pollers onto ONE shared _loginInFlight, a hung flutter_secure_storage read (device memory pressure, corrupted Keychain/Keystore entry) stalls that one login and thus EVERY section indefinitely on “Reconnecting…”. Bound the read: await provider().timeout(_timeout) and map TimeoutException to AuthRequired (or AgentError) so the poller treats it as a normal, recoverable auth-halt (last-known + stale + retry next tick) — never a silent success, never a permanent wedge, never a crash.

HARD invariants (from ADR-0013, architect-confirmed): keep _login() NOT async (read→call→write must stay one synchronous turn so concurrent callers observe a single _loginInFlight); keep the whenComplete(() => _loginInFlight = null) clear so the timeout path also clears the guard; do not change the guard’s shape.

Same cycle, second deliverable (sec-A coverage gap): add a regression test for CONCURRENT warm-token-expiry re-login. Existing tests cover single-caller mid-session expiry (Test 3) and cold-token concurrency (Test 10/10c); the uncovered case is N concurrent callers hitting a just-expired WARM token (401 on the retry path) — they must collapse to ONE _performLogin via the shared guard, not stampede. This test characterises already-correct behaviour reached via the 401-retry path; it may pass on first run (that is expected for a coverage-gap regression test and does not violate RED — the cycle’s failing-RED driver is the timeout test).

Threat model (record in the 6.3 cycle note): attacker-can — not an external attacker vector; a hung/slow secure-store read (memory pressure, corrupted entry) stalls the shared login. mitigation-blocks — the unbounded stall of all six pollers; the read is bounded to _timeout, degrading to a normal recoverable auth-halt. residual-risk — a read that returns slowly-but-under-timeout adds up to _timeout one-time latency to first login (acceptable).

Architecture review. required (top) — SECURITY-TIER — edits _performLogin (authentication logic) + the secure-store password read (secret material). The architect must confirm the timeout wrapping the secret read is correct: TimeoutException maps to AuthRequired/AgentError (never silent success → never an auth-bypass); the not-async _login() single-sync-turn invariant (ADR-0013) is preserved (adding a timeout to the awaited read inside _performLogin must NOT make _login() async); _loginInFlight is cleared on the timeout path (existing whenComplete); the poller degrades to its normal auth-halt (last-known + stale + retry) on timeout. Verdict GO/NO-GO ≤ 400 words; confirm lib/core import-clean. opus per §Security tier.

RED
GREENin lib/core/agent_client.dart _performLogin: wrap the provider() read as `await provider().timeout(_timeout)`; catch/map TimeoutException -> AuthRequired (or AgentError) so the poller auth-halts + retries; KEEP _login() non-async + the whenComplete clear (ADR-0013); no new public API; lib/core import-clean; full suite green
