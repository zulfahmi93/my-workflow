15 cycles, 6 batches. The wins are B02 (six disjoint pure-core sessions in parallel) and B03 (four disjoint widget sessions in parallel); the rest is a short linear chain (foundation → models → widgets → wiring → screen → refinement). Each cycle is one fresh-context session per .claude/rules/cycle-orchestration.md §Session protocol; commit one cycle at a time after the human reviews the diff. ZERO new pubspec deps; ZERO security-tier feature cycles.

How to use

Run B01 (2.1) alone — it creates the generic Poller<T> everything depends on. Then fan out B02’s six sessions (2.2–2.7) — disjoint files, no shared edits, pubspec.yaml stays frozen. Merge, then fan out B03’s four widget sessions (2.8–2.11). Merge, then run 2.12 → 2.13 in sequence (single-owner lib/app.dart then speed_screen.dart). Finally the refinement batch 2.14 → 2.15 in sequence (they re-touch the same files). No cycle is security-tier, so a single code-reviewer APPROVED is the gate (no security-reviewer second pass).

Common contract (applies to every session)

Every session: fresh context; read root /CLAUDE.md + projects/personal/u60-monitor/CLAUDE.md + the rules + this plan’s cycle entry; verify new agent-endpoint shapes against ~/Desktop/tools/open-u60-pro source (never guess fields); honour the architect-gate field; reviewer separation (never self-review); NO-DEFER on BLOCKER/REFACTOR; caveman tone is chat-only (code/tests/commits are idiomatic).

Worktree convention

Optional but recommended for the B02 (six) and B03 (four) parallel sessions: one git worktree per cycle (.worktrees/u60-monitor-2.<n> on branch cycle/2.<n>) so the parallel sessions never touch each other’s tree. The linear cycles (2.1, 2.12, 2.13, 2.14, 2.15) run in the main tree. Sequential in-tree is also fine — concurrent flutter test can race .dart_tool, so serialise the test runs if sharing a tree.

Conflict notes from source

Inter-batch verification

After each batch merge, run the full flutter test + flutter analyze before starting the next batch — the 59 plan-001 tests plus every new test must stay green. B04 (2.12) and B05 (2.13) each require a manual on-device smoke on the real S22 against the real modem (battery/signal/uptime/clients populate; per-tile stale on WiFi drop; one-screen no-scroll at default font).

Stop conditions (across all batches)

Halt + write docs/AUTONOMOUS_RUN_STATUS.md on: architect NO-GO; a missing architect-gate field; a BLOCKER/REFACTOR needing genuine deferral; REVIEW still NEEDS FIX after 3 REFACTOR passes; the test gate unreachable for reasons outside the cycle; a pre-commit hook failure; a cycle demanding out-of-bounds changes (a new dep, a base-URL setter, an AgentClient auth-boundary edit, a subpage). Any cycle that finds it needs a base-URL setter becomes security-tier — STOP and escalate (do not silently add it).

Final state

plan-002 done = the installable app shows, on one no-scroll S22 portrait screen: live Download/Upload (hero), a 2-minute dual up/down history sparkline, battery SoC + charge state (incl. “Charging paused (cap N%)”), 4G/5G type + strength, and operator / uptime / connected-clients glance fields — each tile with its own loading/stale/error state and a11y semantics, all over the existing lazy-auth + transparent-reconnect core, with a motion + theming refinement layer (reduced-motion + AMOLED dark). Zero new deps; the agent password stays in the keystore; no base-URL setter (plan stays out of the security tier).
