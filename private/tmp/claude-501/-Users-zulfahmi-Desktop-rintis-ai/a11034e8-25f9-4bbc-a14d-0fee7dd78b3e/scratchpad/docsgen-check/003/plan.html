3.1

Collapse SpeedPoller onto Poller<SpeedSnapshot>

flutter-expert architect: required (top) Closes: FU-02 (collapse SpeedPoller) + FU-03 (cor…

Delete the legacy lib/core/speed_poller.dart + lib/core/speed_reading.dart; re-point the speed stream onto the generic Poller<SpeedSnapshot> / Reading<SpeedSnapshot> the other four metric pollers already use (FU-02). The generic Poller<T> is behaviourally identical to SpeedPoller (same broad-catch keep-last-known stale path, same AUTH-HALT timer-cancel-keep-controller-open, same idempotent dispose) and adds an isControllerClosed getter; Reading<SpeedSnapshot> is structurally identical to SpeedReading (same const ctor, named params {snapshot, isStale, error}, nullable snapshot) so every SpeedReading(...) is a pure rename.

Migrate the call sites:

  • lib/app.dart (7 refs) — swap the _speedController / _speedPoller / _speedSub / _onSpeedReading types to Reading<SpeedSnapshot>, and the construction to Poller<SpeedSnapshot>(client: …, path: '/api/network/speed', interval: const Duration(seconds: 1), parse: SpeedSnapshot.fromAgentJson) — fromAgentJson’s Map<String,dynamic> → T signature matches the parse param exactly.
  • lib/ui/speed_screen.dart (7 refs) — Stream<Reading<SpeedSnapshot>> / AsyncSnapshot<Reading<SpeedSnapshot>> / StreamBuilder<Reading<SpeedSnapshot>> + the 4 doc lines.
  • lib/core/speed_history.dart (3 refs) — the void add(SpeedReading) signature → void add(Reading<SpeedSnapshot>) + 2 doc lines.

Delete the now-redundant test/core/speed_poller_test.dart (its 7 cases are a strict subset of poller_test.dart; the only extra it exercised — the real SpeedSnapshot.fromAgentJson parse — is independently covered by speed_snapshot_test.dart) and migrate SpeedReading → Reading<SpeedSnapshot> renames, with explicit <SpeedSnapshot> type args on factory-helper return types, in test/ui/speed_screen_test.dart (13 refs), test/ui/integrated_screen_test.dart (6 refs), test/core/speed_history_test.dart (2 refs).

Sweep the dangling doc-symbol refs after deletion (deleting the classes otherwise raises analyzer dangling-doc hints): lib/core/core.dart barrel-doc (full plan-002 listing refresh — folds FU-03, since the barrel still stops at 1.6), lib/core/reading.dart “mirrors [SpeedReading]” line, lib/ui/widgets/monitor_header.dart FreshnessState [SpeedReading] refs (×2), test/app_flow_test.dart [SpeedPoller]/[SpeedReading] explanatory comments (×3, doc-only).

Architecture review. required (top) — Touches the core polling contract (Poller<T>/Reading<T>) that all five metric streams depend on. The gate must confirm the auth-halt (AuthFailure/AuthRequired → cancel timer, keep controller open), broad-catch keep-last-known + mark-stale, and idempotent-dispose semantics are preserved by construction (they already live in Poller<T>), and that deleting speed_poller_test.dart loses zero coverage because poller_test.dart is a verified test-by-test superset and speed_snapshot_test.dart covers the parse path. Sonnet not top: no security surface is touched — auth-halt logic is unchanged and already-tested, untrusted-modem-JSON parsing stays in SpeedSnapshot.fromAgentJson (unchanged).

RED
GREENdelete speed_poller.dart + speed_reading.dart; re-type the 13 call sites to Poller<SpeedSnapshot>/Reading<SpeedSnapshot>; explicit type args on test factory helpers; sweep the 7 dangling doc refs

3.3

Snap one-shot motion on a reduced-motion toggle; lock recovery haptic

flutter-expert architect: none Closes: F2 (motion widgets miss didChangeDependen…

_StaleFadeState and _CountUpTextState (motion.dart) override only didUpdateWidget, so a runtime system reduced-motion toggle — a MediaQuery change firing didChangeDependencies but NOT didUpdateWidget — leaves an in-flight 250–400ms animation running instead of snapping to its final frame (F2).

  • Add didChangeDependencies() to both, guarded by _reducedMotion && _controller.isAnimating: StaleFade snaps _controller.value = widget.isStale ? 1.0 : 0.0; CountUpText does _controller.stop(); _from = null; _to = null;. Mirror _DotIndicator._syncPulse’s pattern but DO NOT stomp a non-reduced-motion in-flight one-shot (the isAnimating + _reducedMotion guard is what makes this safe — a naive copy of _syncPulse onto a one-shot controller could restart/stomp a live animation).
  • Do NOT modify _DotIndicator (already correct — its REPEATING pulse genuinely needs the hook) or monitor_header.dart _flash (one-shot, self-heals on next trigger). Grounding caveat: for the one-shot widgets this is defensive-consistency hardening, not a steady-state bug fix — they self-correct on the next trigger; the hook makes a mid-flight toggle correct too.

Pair F6: add a reducedMotion:true variant of the haptic-recovery test that locks the intended behaviour — the recovery haptic fires BEFORE the if (!_reducedMotion) flash gate (monitor_header.dart:115), so it must tap even under reduced motion. The guard passes as-is (it is a lock against future regression, not a bug-find).

Architecture review. none — Localized, defensive motion-lifecycle hook mirroring an existing in-repo pattern (_DotIndicator); pure visual/haptic, no data or auth surface. The one subtle risk (stomping an in-flight one-shot) is contained by the isAnimating guard and caught by the code-reviewer gate.

RED
GREENtwo guarded didChangeDependencies hooks on _StaleFadeState/_CountUpTextState (isAnimating + _reducedMotion); the F6 guard passes as-is

3.5

Close the AgentClient http.Client on re-auth; drop dead fake flags

flutter-expert architect: none Closes: FU-07 (AgentClient holds an http.Client w…

AgentClient holds a default-constructed http.Client with no close(), so on re-auth a fresh AgentClient is built per _startPollers and the old client’s connection pool is left to the 15s idle-timeout/GC (FU-07).

  • Add AgentClient.close() delegating to _client.close() (and a doc line on the Cycle-1.4-locked class doc noting the additive resource lifecycle — the auth flow steps are unchanged).
  • In app.dart track the active AgentClient as a _SpeedHomeState field; close-then-null it in _disposePollers() (called on both re-auth and final dispose; a null guard prevents double-close) and reassign it in _startPollers() — release the pool promptly after subs are cancelled + pollers disposed (cancel → dispose → close ordering).

NOT security-tier: close() releases the http.Client only; no auth/token/password/base-url code path changes. The reviewer must still confirm no auth-path regression.

Fold FU-08: delete the unused FakeMultiClient edge-mode flags (battCapPause, signalAbsent, signalNotConnected, signalSentinel, nsaMislabel, signal503) and their dead branches — no test toggles them (verified dead scaffolding) — and add the bool closed close-spy the re-auth assertion needs.

File dep on 3.1: both write lib/app.dart + test/app_flow_test.dart, so 3.5 must run after the collapse to avoid a working-tree conflict (deps:[3.1]).

Architecture review. none — Connection-pool resource hygiene on an already-tested dispose path. NOT security-tier: close() releases the http.Client only and touches no auth/token/password/base-url code path (the Cycle-1.4 auth flow is unchanged). The one correctness edge (close ordering vs in-flight request, double-close on final dispose) is bounded by cancel-then-dispose-then-close ordering + a null guard, and verified by the code-reviewer gate which must also confirm no auth-path regression.

GREENAgentClient.close() -> _client.close(); track the active client as a _SpeedHomeState field, close-then-null in _disposePollers, reassign in _startPollers; delete dead FakeMultiClient flags; add the closed spy
