u60-monitor — Polish & Debt Paydown (plan-003)

Close the open plan-001 / plan-002 follow-ups plus the 8 post-plan-002 verification findings in six small TDD cycles: fold the legacy SpeedPoller onto the proven generic Poller<T>, tokenize the signal-tile stale dot, snap one-shot motion on a runtime reduced-motion toggle, require explicit chart trace colours, close the AgentClient http.Client on re-auth, and tighten the StatusStrip count finder. ZERO new pubspec deps, ZERO security-tier cycles; the dormant ADR-0002 base-URL invariant is not triggered.

6 TDD cycles 2 parallel batches ~50% — Batch B's five polish cycles (3.2–3.6) are write-disjoint and free of shared test-resource collision, collapsing to ~1 wall-step; the only hard serial edge is 3.1 → 3.5 (3.5 shares lib/app.dart + test/app_flow_test.dart with the collapse). The serial spine is just two cycles: 3.1 → 3.5. wall-time saved 6 / 6 shipped

Context

plan-003 is the polish + debt-paydown plan for u60-monitor. plan-001 shipped the live-speed MVP and plan-002 shipped the Glance Dashboard (history sparkline, battery, signal, status strip) on one no-scroll S22 screen. Both plans deferred a tail of small, in-scope follow-ups so the headline feature cycles stayed un-churned. plan-003 discharges that tail.

Source of truth — four gather passes feed exactly 12 actionable items, deduplicated into 6 cycles:

  1. plan-001 follow-ups — 9 items, all but one already resolved in Cycles 1.5–1.8 / post-run. The sole still-open item is the dormant base-URL setter invariant (ADR-0002), carried forward, not discharged here.
  2. plan-002 follow-ups — 19 items (14 plan rows + 5 cycle-note deviations). The actionable subset: collapse SpeedPoller onto Poller<SpeedSnapshot> (FU-02), refresh the core.dart barrel-doc (FU-03), tighten the StatusStrip finder (FU-06), add AgentClient.close() (FU-07), delete dead FakeMultiClient edge flags (FU-08), tidy the shouldRepaint comment (FU-15). The four on-device S22 smokes (FU-09/10/13/14) and the dormant invariants (FU-01, FU-17) need no code.
  3. 8 verification findings — F1 (signal-tile stale dot ignores the staleIndicator token), F2 (motion widgets miss didChangeDependencies), F3 (chart painter’s MonitorColors.light fallback footgun), F5 (stale shouldRepaint comment), F6 (a haptic reduced-motion regression guard), F7 (an understated contrast comment) are folded into the cycles; F4 (cycle-note schema has no per-pass reviewer slot) and F8 (two prior commit subjects exceed 50 chars) are non-code, tracked in §Open questions / §Cycle follow-ups.
  4. Code-scope feasibility — confirmed the SpeedPoller collapse is GREEN with zero coverage loss (poller_test.dart is a verified test-by-test superset of speed_poller_test.dart; speed_snapshot_test.dart covers the parse path) and grounded the reduced-motion fix as defensive-consistency, not a steady-state bug, for the one-shot widgets.

Six cycles, two batches. Batch A = 3.1 solo (the one medium item — the core polling-contract collapse, opus architect gate before RED). Batch B = 3.2–3.6 — write-disjoint polish/debt cycles. 3.5 carries a file-level dep on 3.1 (both write lib/app.dart + test/app_flow_test.dart); 3.2/3.3/3.4/3.6 are genuinely disjoint and staged after A only for clean review sequencing. Critical path = 3.1 → 3.5.

ZERO new pubspec deps — every cycle edits or deletes existing files; no package is added (an out-of-bounds STOP if one is). ZERO security-tier cycles — every cycle lands on the audited read-only display/telemetry boundary (lib/ui cosmetic colour/motion, the chart, test files) or adds pure resource hygiene. Cycle 3.5 is the only one touching an auth-sensitive file (lib/core/agent_client.dart), but it adds only an http connection-pool close() and changes no auth/token/password/base-url code path — the Cycle-1.4-locked auth flow is untouched — so the code-reviewer gate suffices (no security-reviewer second pass); the reviewer must still confirm no auth-path regression.

The ADR-0002 base-URL invariant is NOT triggered. plan-003 adds no base-URL / Settings setter; saveBaseUrl stays test-only and baseUrl() returns the default 192.168.0.1:9090. The invariant is the only genuinely security-tier item across all four gather sources and it is dormant — carried into §Cycle follow-ups + ADR-0002, not discharged. If any future cycle wires a user-suppliable base URL, that cycle becomes security-tier (opus architect gate + security-reviewer) and must validate http(s) scheme + private/LAN host in-cycle before the Bearer password is sent.

No new pubspec deps. Unlike plan-002 (whose Cycle 2.1 was the sole sanctioned pubspec-touch), plan-003 has no pubspec-touch cycle at all — any dep add is an out-of-bounds STOP. The frozen-pubspec rule from plan-001/plan-002 stands.

Architecture rule (unchanged + enforced): pure-Dart core stays free of flutter/material/dart:ui; a flutter import under lib/core/ is an instant review BLOCKER. Cycle 3.1 re-points the speed stream onto the generic Poller<T>/Reading<T> already living in lib/core/ — it removes the duplicated SpeedPoller/SpeedReading skeleton, it does not add a new core surface.

TDD cycle format

See .claude/rules/cycle-orchestration.md (paired with tdd.md + commit.md). Reviewer separation, architect gate, NO-DEFER, subagent prompt skeleton, reviewer hallucination guard — all unchanged. Architecture-review value on every cycle is mandatory (missing field → STOP). No cycle is security-tier; the architect (3.1) and the reviewer (all cycles) must still confirm this per cycle, not assume it.

CYCLE X.Y — [behaviour name]
RED      (Model - Agent):          exact failing test assertions (or, for 3.1, the migration compile-break)
GREEN    (Model - Agent):          minimal code to pass
REVIEW   (Model - code-reviewer):  issues list; never writes code
REFACTOR (Model - Agent):          domain expert applies review feedback

Model rules (per user directive — overrides the default tier map for this plan: architect gates + REVIEW use opus; RED/GREEN/REFACTOR default sonnet; never haiku):

Cycle complexity RED GREEN REVIEW REFACTOR
Architecture-gated structural refactor (3.1) sonnet (architect opus) sonnet opus sonnet
Cosmetic / motion / resource-hygiene polish (3.2–3.6) sonnet sonnet opus sonnet

Agent roles:

Agent Role

Out of scope (plan-003)

  • A base-URL / Settings setter — deliberately not added (keeps the whole plan out of the security tier per ADR-0002). The invariant is carried, not discharged. If ever added, that cycle is security-tier with in-cycle http(s)+private/LAN validation.
  • Sparkline “draw-in” / point-append animation — a standing won’t-do invariant (FU-17): a frame-driven draw-in would breach the chart’s no-ImplicitlyAnimatedWidget guard and exceed the ≤1/s repaint budget. Cycle 3.4 explicitly preserves this guard.
  • The two-up half-width Row for Battery + Signal — the current full-width vertical stack is an architect-sanctioned fallback (BatteryTile text overflows ~108dp at 1.3× text scale). Restoring the Row needs typography rework + a UX call + an integrated_screen_test re-run — too much for a polish plan (open question, not a cycle).
  • MonitorHeader named-header semantics — excludeSemantics:true deliberately suppresses the app-name title so the composed Semantics announces only the load-bearing state (Live/Stale/Reconnecting). No a11y directive to override; left as a documented deliberate omission.
  • Precise connected-client count — agent-side, not ours. /api/wifi/status clients_total leaks the WiFi PSK; a precise count needs a count-only endpoint added to the zte-agent in open-u60-pro (a separate repo). The dhcp_leases-length count stays.
  • On-device Samsung S22 deploy & device-verify smokes — the deferred plan-002 device smokes (and the plan-001 1.8 iOS install/trust step) are a manual human deploy pass; no agent can drive a physical phone. Tracked as a single §Cycle-follow-ups note, not a TDD cycle.
  • cycle-note schema per-pass reviewer roster (F4) — a repo-wide docs-gen tooling change affecting every project’s cycle notes; out of u60-monitor’s plan-003 scope (open question for a separate infra task).
  • Any new pubspec dep — there is no pubspec-touch cycle; a mid-plan dep add is an out-of-bounds STOP.

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
