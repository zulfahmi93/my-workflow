plan-011 closes the security and data-truth items of docs/open-issues-2026-07-19.md. Five cycles, four security-tier, ZERO new deps. The headline is that the ADR-0002 base-URL invariant — carried unfulfilled by six consecutive plans — gets discharged defensively rather than carried a seventh time, and that the app stops asserting a data plan the firmware may consider inactive.

How to use

Sequencing. Run SEQUENTIALLY on main, one commit per cycle: 11.1 (base-URL validator) → 11.2 (confused deputy) → 11.3 (plan.enabled) → 11.4 (release signing) → 11.5 (.env).

11.1 → 11.2 is a hard order: both edit lib/core/agent_client.dart. 11.3, 11.4 and 11.5 are genuinely file-disjoint and could parallelize, but the run stays sequential — each cycle’s gate runs the whole flutter test suite (cross-attributable in a shared tree), and four of five cycles carry a security-reviewer second pass, where clean attribution matters most. The nested repo’s worktrees must be managed MANUALLY in any case.

Commit scopes: core (11.1, 11.2, 11.3), infra (11.4), chore/docs (11.5).

Relationship to the other plans. plan-009 cycle 9.1 rewrites the project guide, which both 11.4 (signing setup notes) and 11.5 (.env in Local-dev quirks) want to add to — whichever lands second reconciles. plan-010 is file-disjoint from this plan entirely.

Common contract (applies to every session)

Architect gate: required (opus) on 11.1, 11.2 and 11.4; deferred to 11.1 on 11.5; none on 11.3. MODEL-TIER POLICY: architect gates + ALL REVIEW + security 2nd pass on opus; RED/GREEN/REFACTOR default sonnet; never haiku.

Four of five cycles are security-tier (11.1, 11.2, 11.4, 11.5) and each takes the security-reviewer second pass — BOTH reviewers APPROVED before COMMIT — and each records a threat model in its cycle note (attacker-can / mitigation-blocks / residual-risk), per the plan-006 6.3 precedent. 11.3 is not security-tier; see §Security-tier ruling for why.

Two recurring must-checks across this plan, because both defects share a shape — a guard that appears present but silently degrades:

  • No silent fallback, anywhere. A rejected base URL must not quietly become the default (11.1); an absent keystore must not quietly become the debug key (11.4). In both cases the fallback looks like success while producing exactly the condition the cycle was meant to prevent, which is strictly worse than a visible failure.
  • Absence is not falsehood. A missing enabled field must not be read as false (11.3), or every agent build predating the field silently loses its plan display.

Workflow execution. Cycles run via .claude/workflows/tdd-cycle.js ({ project: "u60-monitor", projectPath: "projects/personal/u60-monitor", plan: "011", cycle, greenAgent: "Flutter Expert", redAgent: "Flutter Expert", securityTier }). 11.4’s verification is command-driven rather than unit-testable and its outputs are recorded in the cycle note. Commits stay OUTSIDE the workflow.

Worktree convention

Not applicable — cycles run sequentially on main. (Harness note, carried from plan-004/007/008/009/010: isolation:worktree creates an app-less ROOT-repo worktree because /projects/ is gitignored at the monorepo root — the nested u60-monitor repo’s worktrees must be managed MANUALLY.)

Inter-batch verification

After each cycle: full flutter test green + flutter analyze clean + zero flutter/material/dart:ui import under lib/core + a fresh code-reviewer (opus) APPROVED + (security-tier) a security-reviewer (opus) APPROVED; update the cycle status: in plan-011.yaml; file docs/cycles/11.X.yaml with its threat model (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). One commit per cycle per commit.md.

Three checks specific to this plan:

  • git status shows no key material after 11.4 — no *.jks, no *.keystore, no key.properties. Check the actual working tree, not just the diff.
  • No secret value appears in any cycle note, commit message or agent report — 11.4 and 11.5 both handle files that carry or imply credentials. Key names only.
  • ADR-0013’s login invariants survive 11.1 AND 11.2 — _login() non-async, whenComplete clears _loginInFlight on every path including any new rejection path. Both cycles touch that file.

Stop conditions (across all batches)

  • 11.1 guards only ONE entry point (setter or constructor, not both) → BLOCKER. They fail differently and one open path defeats the invariant.
  • 11.1 silently falls back to the default base URL on rejection → BLOCKER. That masks a tampered store — the subtler bug.
  • A credential is sent to a URL before validation → BLOCKER; that is the invariant’s entire point.
  • 11.2 restates the deferral a third time instead of closing or formally accepting → STOP. Not an available outcome.
  • 11.2’s CLOSE route requires _login() to become async → STOP and escalate; that breaks the ADR-0013 single-sync-turn invariant and must not be traded away.
  • 11.3 reads an ABSENT enabled as false → BLOCKER; it silently strips the plan display from every older agent build.
  • 11.4’s release build silently falls back to the debug key when the keystore is absent → BLOCKER. Verify by running it, not by reading the config.
  • Any key material, password or .env value is committed, printed, or echoed into build output, a cycle note, a commit message or a report → BLOCKER.
  • An agent generates key material on the owner’s behalf (11.4) → STOP; that is an owner action.
  • 11.5 finds a LIVE credential in .env → surface it and recommend rotation; rotation is an owner action, not an agent one.
  • A base-URL setter UI is added (out of scope for this plan) → STOP; that is its own security-tier cycle.
  • /api/network/client-traffic work creeps in (A7) → STOP; deliberately out of scope on both privacy and verifiability grounds.
  • Any dependencies: add (none planned) → out-of-bounds STOP.

Final state

Test trajectory: baseline 381 (higher if plans 008/009/010 landed first) → roughly +7 (11.1) +3 (11.2) +5 (11.3) +0 (11.4, command-verified) +0 (11.5) ≈ +15.

The ADR-0002 base-URL invariant is discharged, not carried a seventh time: both saveBaseUrl and the AgentClient constructor reject non-http(s) schemes and non-LAN hosts explicitly, before any credential leaves the device, with no silent fallback — and any future settings cycle becomes routine rather than dangerous. The confused-deputy risk the code itself flagged is either closed in code or formally accepted with a test that pins the constraint, and its comment no longer says “needs revisiting”. The app honours the firmware’s plan.enabled flag, so it can no longer assert a data plan the device considers inactive, while older agents that never sent the field behave exactly as before. Android release builds are signed with a real key that is never committed, and fail loudly rather than silently debug-signing. The plaintext .env is disposed of either way.

ZERO new deps. No git remote — never push.

Remaining from the backlog: the housekeeping plan (§D3 nits + A14 test hardening), the root-monorepo items (§D4/D5/D6, A17, A20), A7’s client-count switch (owner privacy call + unverifiable endpoint), and the on-device deploy pass.
