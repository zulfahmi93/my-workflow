u60-monitor — Morph fidelity (plan-010)

plan-007 spent ten cycles building a frame-accurate numeric morph, and on five surfaces it silently does not run. ADR-0014:179-187 is a forward-lock: unit-bearing single-number surfaces MUST pass the CLEAN numeric run with the unit as a static sibling. At HEAD every named exemplar violates it — '$percent%', 'PEAK $peakLabel', 'CAP ${pct}%', '−N dBm', 'OF ${formatBytes(limit)}' and the two formatBytes volume readouts all reach the primitive as combined strings, double.tryParse fails, direction == 0, and didUpdateWidget returns without starting the ticker. The result is a whole-string cross-fade where digits should roll. No test fails; the effect just quietly stopped working, and plan-007.yaml:83 states the CONTRADICTING rule so a reader hits wrong guidance first. Also: _shrinkOverlay paints unclipped into negative x with no assertion on where it lands, and _kHeadroom = 1.12 is type-level unreachable while ADR-0007 still calls it live design. 7 cycles. ZERO new deps.

7 TDD cycles 3 parallel batches Moderate — 10.2/10.3/10.4 are one file each and genuinely disjoint, and 10.5/10.6 are disjoint from all of them, so five of seven could parallelize once 10.1's gate lands. The run executes SEQUENTIALLY on main: each cycle's gate runs the whole `flutter test` suite, which is cross-attributable in a shared tree (the plan-004/005/006 lesson), and 10.2's ~12-assertion churn makes a clean attribution especially valuable. Context

The morph you already paid for is not running. ADR-0014:179-187 is explicit and it names the exact surfaces:

Unit-bearing single-number surfaces (percent '254%', dBm, PEAK) MUST pass the CLEAN numeric run to the primitive with the unit as a static sibling (the SpeedTwin whole/frac/unit precedent), so direction stays meaningful and the digits roll. Whole-string cross-fade (direction 0) is reserved for genuine placeholder / empty / multi-token strings ('—', '', '3d 4h').

Verified at HEAD 1ef8038, every named exemplar violates it:

Surface Call site Value passed
percent data_usage_section.dart:355 '$percent%' — literally the '254%' the ADR cites
PEAK speed_history_chart.dart:203 'PEAK $peakLabel' (peakLabel already carries its unit)
CAP battery_tile.dart:217 'CAP ${s.chargeLimitPct}%'
dBm footer_triplet.dart:51 '−${signal.rsrpDbm!.abs()} dBm'
OF data_usage_section.dart:372 'OF ${formatBytes(limit)}'
volumes data_usage_section.dart:405,409 formatBytes(rx) / formatBytes(tx) → e.g. '45.0 GiB'

The mechanism, traced. animated_numeric_text.dart:254 — if (diff.direction == 0) { … } — takes the neutral branch, sets _controller.value = 1.0 and returns without starting the ticker. direction comes from numeric_transition.dart’s cleaned double.tryParse, which fails on any of the strings above. So the build-time AnimatedSwitcher cross-fades the whole string and no digit ever rolls.

Why no test caught it. Nothing asserts that a roll occurred. Cycle 7.6 knowingly deviated — cycles/7.6.yaml:87-94 records the choice to keep ~12 find.text('PEAK …') assertions green and closed the finding as “No action”. That is the whole failure: an assertion suite that pins the rendered string is satisfied identically whether the digits rolled or cross-faded, so the primitive can silently stop working on a surface and the suite stays green forever.

There is a working reference implementation in the same file. data_usage_section.dart:298-312 — the hero readout — already does exactly what the forward-lock prescribes: AnimatedNumericText(value: value, style: heroStyle) with the unit as a sibling Text(unit, …) inside a Row. battery_tile.dart:186 ('${s.capacityPct}') and speed_twin.dart:276,280 (whole / frac) are likewise compliant. So this plan is not inventing a pattern; it is applying an in-repo one to the surfaces that were skipped.

The contradiction that must be resolved, not papered over. plan-007.yaml:83 states a rule that CONTRADICTS ADR-0014:179-187 — the ADR’s own text acknowledges this, saying the static-sibling rule “overrides §Numeric-surface-inventory’s ‘trailing letters ride as static glyph columns inside the string’ for %/dBm.” So the plan and the ADR disagree in writing, the code follows the plan, and the ADR is the accepted record. Cycle 9.3 of plan-009 was explicitly forbidden from reconciling this because it has code attached. Cycle 10.1’s architect gate owns it.

What is NOT a violation and must not be “fixed”. Genuine multi-token strings are correctly on the cross-fade path: 'resets day ${s.plan.clearDay}' (data_usage_section.dart:238), the chart’s elapsedLabel (:210), and the uptime triplet ('3d 4h'). The forward-lock reserves direction 0 for exactly these. A cycle that splits them has misread the rule and is a BLOCKER.

Two smaller defects ride along, both verified.

  • _shrinkOverlay is unbounded and unasserted. animated_numeric_text.dart:481-499 is Positioned(left:0, top:0, bottom:0, width:0) + OverflowBox(alignment: centerRight, maxWidth: infinity) inside a Stack(clipBehavior: Clip.none) at :451. Its own doc comment (:478-480) states the intent plainly: the dropped glyphs “paint centered on the RIGHT edge of the (zero-width) box — i.e. entirely in the negative-x region just before the roll row’s own left edge.” That is by design (cycle 7.9’s paint-only zero-layout drop, ADR-0014 amended). What is NOT by design is that nothing bounds how far left it reaches and no test asserts where it lands. Shipped in HEAD itself. The backlog’s geometry estimate — a ~36-40px tabular digit advance against speed_twin.dart:242’s 16px horizontal padding, i.e. a ~20-24px overrun past the 1px VerticalDivider at :91-95 — is an estimate, and the one existing SpeedTwin drop test uses UL 30→18, which has no digit drop, so the divider-crossing path is entirely unexercised. The collision question is decidable in-repo by a widget test; only “does it read graceful” needs eyes.
  • _kHeadroom = 1.12 is type-level unreachable. sparkline_geometry.dart:67 is final rawMax = max ?? (dataMax * _kHeadroom); and the painter — its sole production caller — always passes a non-nullable max. The visual need was met later by a different mechanism (topInset), plan-004.yaml:954 even names the bypass, but nothing records the supersession and ADR-0007:46,95 still states ×1.12 as live design.

Scope discipline. This plan draws from docs/open-issues-2026-07-19.md items A2 / BUG-1, A5 / BUG-2, A4 / BUG-4 and nothing else.

TDD cycle format

See .agents/rules/cycle-orchestration.md (paired with tdd.md + commit.md). Reviewer separation, architect gate, NO-DEFER, subagent prompt skeleton, reviewer hallucination guard — unchanged. Architecture-review value on every cycle is mandatory (missing field → STOP).

CYCLE 10.X — [surface]
ARCHITECT (opus, 10.1 only):       GO/NO-GO ≤ 400 words; locks the split pattern + the ADR reconciliation
RED      (sonnet - flutter-expert): a test that FAILS because the digits do not roll
GREEN    (sonnet - flutter-expert): split the string; unit becomes a static sibling
REVIEW   (opus  - code-reviewer):   issues list; never writes code
REFACTOR (sonnet - flutter-expert): apply review feedback

The RED phase is unusually load-bearing in this plan and its shape is locked by 10.1. The defect is precisely that the existing tests cannot tell a roll from a cross-fade. A RED that asserts the rendered string proves nothing — the string is identical either way, which is exactly how the regression survived. Each cycle’s RED must assert the mechanism: that a per-column roll occurred (glyph columns present / the controller ran / direction != 0 for the diff the surface produces). 10.1’s architect gate defines the canonical assertion so all six surfaces are proven the same way rather than six ad-hoc approximations.

Model rules (standing project directive — overrides the default tier map: architect gates + ALL REVIEW use opus; RED/GREEN/REFACTOR default sonnet; never haiku):

Cycle kind RED GREEN REVIEW REFACTOR
Pattern-locking (10.1) sonnet (architect opus) sonnet opus sonnet
Surface adoption (10.2–10.4) sonnet sonnet opus sonnet
Geometry + dead code (10.5, 10.6) sonnet sonnet opus sonnet
Close (10.7) — sonnet opus sonnet

Agent roles: software-architect — the 10.1 gate only (opus), never RED/GREEN. flutter-expert — RED/GREEN/REFACTOR. code-reviewer — REVIEW only (opus). Optionally consult frontend-design:frontend-design on 10.4, where the split interacts with a live Flexible-ellipsized operator sibling.

What cycle 10.1's architect gate must decide

10.1 is the only gated cycle and it locks the whole plan. Four rulings, all of which later cycles inherit:

  1. The split pattern. data_usage_section.dart:298-312 is the in-repo reference: AnimatedNumericText(value: <clean numeric run>) + the unit as a sibling Text in a Row. Confirm it generalises to a prefix ('PEAK ', 'CAP ', 'OF ') as well as a suffix ('%', ' dBm', ' GiB'), and rule on baseline alignment, spacing, and whether the prefix is a sibling Text or stays inside the styled run. formatBytes returns a combined '45.0 GiB', so the volume surfaces need a value/unit split at the format layer or a widget-side partition — decide which, once, for both.

  2. The canonical roll assertion. The RED shape every surface uses. It must fail on the current code and pass only when digits actually roll. Asserting the rendered string is forbidden — that is the assertion class that let this regress. Options include finding the per-column glyph widgets, pumping mid-transition and asserting intermediate state, or asserting diffNumericGlyphs yields direction != 0 for the value the surface now passes. Pick one and make it reusable.

  3. The ADR-0014 vs plan-007:83 reconciliation. They contradict in writing; the code follows the plan; the ADR is the accepted record. ADR-0014:185-187 already asserts the static-sibling rule overrides §Numeric-surface-inventory. Ratify that direction (or overturn it with reasons) and record the outcome so plan-007.yaml:83 stops giving a reader the wrong rule first. plan-009 cycle 9.3 was explicitly forbidden from touching this; it is yours.

  4. The assertion-churn policy for 10.2. Roughly 12 find.text('PEAK …') assertions break once PEAK is split, because the text is no longer one node. Rewriting them is expected and correct. But the reviewer needs a stated bar to judge each rewrite against — a rewrite that merely re-pins the new string reproduces the original blind spot. Rule on what a rewritten assertion must prove.

NOT in this gate: whether _shrinkOverlay should be clipped (10.5’s own finding decides that from a measured test), and whether _kHeadroom is retired or wired (10.6 — a two-line call either way, gated by review).

What this plan does NOT change

  • The primitive itself is not modified for BUG-1. AnimatedNumericText and numeric_transition.dart are correct; the call sites pass them the wrong thing. A cycle that changes the primitive to parse combined strings is solving the wrong problem — ADR-0014:184-186 explicitly rejects it: “A scalar direction cannot distinguish a roll-able '254%' from a cross-fade '3d 4h' when both fail whole-string parse — hence the static-sibling rule.” 10.5 is the only cycle that touches the primitive, and only for the overlay bound.
  • Genuine cross-fade surfaces stay cross-fading: 'resets day N', the chart elapsedLabel, the uptime triplet. Splitting them is a BLOCKER.
  • No layout redesign. ADR-0009 per-tile freshness and ADR-0010 sticky-footer structure are untouched. The split must not change any surface’s outer size or introduce overflow at 360dp / 1.3× text scale — REVIEW checks this per cycle.
  • No new dependency, no new abstraction.
  • The on-device “does it read graceful” judgement for _shrinkOverlay stays with the human deploy pass. 10.5 decides only the measurable half.

Out of scope (plan-010)

Tracked in docs/open-issues-2026-07-19.md, deliberately not bundled:

  • plan-011 — plan.enabled, the ADR-0002 base-URL validator, the confused-deputy risk, release signing.
  • plan-009 — the guide rewrite, dead-path sweep, ADR accuracy, README. Note the interaction: plan-009 cycle 9.3 corrects ADR-0014:66’s fade-span number and is forbidden from touching the forward-lock at :179-187. If 9.3 has already landed, 10.1 must not revert its fade-span correction.
  • Chart axis re-scaling. plan-008 sharpens PEAK and the auto-ranged ceiling will re-range more often; whether that wants a log axis or a percentile ceiling is its own plan. 10.6 touches _kHeadroom only as dead code, and must not become an axis redesign.
  • The chart ELAPSED whole-string cross-fade (cycles/7.6.yaml:99) — a taste call for the deploy pass, and elapsedLabel is a legitimate multi-token cross-fade under the forward-lock. Not a defect.
  • Housekeeping nits (§D3) and test hardening (A14) — a later plan.

Standing invariants preserved

  • ADR-0014 primitive contract upheld — the fix is at the call sites, which is what the ADR prescribes.
  • ADR-0009 per-tile freshness / ADR-0010 sticky footer untouched; no outer-size change on any surface.
  • Semantics — every split surface must keep announcing the FULL value (number + unit) as one label. Splitting the visual string must NOT split the accessible one; a screen reader announcing '254' and '%' separately is a regression and a REVIEW must-check.
  • Reduced motion honoured — a split surface must still render a single static Text when motion is off.
  • tabular figures preserved on every split run (width stability; the 7.8 lesson).
  • pure-Dart lib/core boundary upheld (10.6).
  • no test weakened — 10.2’s assertion rewrites are corrections to a proven-blind assertion class, and each must prove strictly MORE than the one it replaces (10.1 ruling 4).

Conventions in play

Every cycle runs through the same disciplined loop, defined in the shared rules under .agents/rules/.

Architect gate

Each cycle carries an architecture-review tier (top, mid, none, or deferred). Legacy provider aliases are normalized while loading. A fresh software-architect returns a GO / NO-GO verdict before RED for the non-trivial ones.

Reviewer separation

REVIEW is performed by a fresh code-reviewer sub-agent — never self-review. Security-tier cycles add a security-reviewer second pass.

NO-DEFER

Every [BLOCKER] and [REFACTOR] finding is resolved in the same cycle’s REFACTOR pass. Scope discipline is not a reason to defer an in-scope finding.
