If either is a genuine multi-token string (the uptime triplet reads e.g. '3d 4h'), it is a legitimate cross-fade and MUST be left alone; if either is a clean numeric run it already complies. Bound _shrinkOverlay and assert where the dropped glyph lands

flutter-expert architect: none

The measurable half of a NIT currently parked on the human deploy pass.

animated_numeric_text.dart:481-499 is Positioned(left:0, top:0, bottom:0, width:0) wrapping an OverflowBox(alignment: centerRight, minWidth: 0, maxWidth: infinity, fit: deferToChild), inside a Stack(clipBehavior: Clip.none) at :451. The widget’s own doc comment (:478-480) states the intent: the dropped glyphs “paint centered on the RIGHT edge of the (zero-width) box — i.e. entirely in the negative-x region just before the roll row’s own left edge.”

That is by design — cycle 7.9’s paint-only, zero-layout digit drop, which is exactly what keeps the outer width constant and prevents the end-of-roll snap. This cycle does not reopen it.

What is not by design: nothing bounds how far left it reaches, and no test asserts where it lands. Shipped in HEAD 1ef8038 itself.

Two deliverables:

  1. The collision test. In SpeedTwin, a digit drop in the UPLOAD column paints leftward toward the 1px VerticalDivider (speed_twin.dart:91-95) across only horizontal: 16 padding (:242). Assert the dropped glyph’s painted position against the divider rect — e.g. getTopLeft(find.text('1')).dx on an upWhole '100' → '99' transition. The existing SpeedTwin drop test uses UL 30 → 18, which has no digit drop, so this path is entirely unexercised. The backlog’s ~20-24px overrun figure is an estimate derived from a 66px _wholeFontSize (:160) against 16px of padding — measure it, do not assert the estimate.
  2. Bound the overlay if the measurement shows it crosses. The prior art from 7.9’s own follow-up (cycles/7.9.yaml:87) is a vertical-only clip that keeps horizontal Clip.none — that preserves the intended leftward paint while cropping the slide tail. Apply the minimum that fixes what the measurement actually shows.

If the measurement shows no collision, that is a valid and valuable outcome. Record it, keep the test as a regression guard, and retire the deploy-pass NIT for the collision half — the “does it read graceful” judgement still belongs to a human.

STOP condition: if the measurement indicates the negative-x design is itself wrong (rather than merely unbounded), do not redesign it here — that reopens an architect-locked ADR-0014 decision and requires a gate.

This cycle does not revisit that decision; it adds the bound and the assertion 7.9 never wrote, and lets a measured test decide whether a clip is needed. If the measurement shows the design itself is wrong rather than merely unbounded, that IS an architecture question and a STOP condition. Gated by an opus code-reviewer pass. NOT security-tier.
