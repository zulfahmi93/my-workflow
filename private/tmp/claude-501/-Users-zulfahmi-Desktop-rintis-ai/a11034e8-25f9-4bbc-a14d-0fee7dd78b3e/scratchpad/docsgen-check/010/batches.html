plan-010 makes the plan-007 numeric morph actually run on the surfaces an accepted ADR says it must. ADR-0014:179-187 requires unit-bearing single-number surfaces to pass a clean numeric run with the unit as a static sibling; at HEAD six call sites pass combined strings instead, so double.tryParse fails, direction == 0, and the ticker never starts. No test catches it because the assertions pin rendered strings, which are identical whether the digits rolled or cross-faded. Seven cycles, none security-tier, ZERO new deps. Scope is items A2/BUG-1, A5/BUG-2 and A4/BUG-4 of docs/open-issues-2026-07-19.md.

How to use

Sequencing. Run SEQUENTIALLY on main, one commit per cycle: 10.1 (DataUsageSection + the gate) → 10.2 (PEAK + assertion unwind) → 10.3 (CAP) → 10.4 (dBm) → 10.5 (dropped-glyph bound) → 10.6 (_kHeadroom) → 10.7 (close + audit).

10.1 must be first and must be gated. It rules on four things every later cycle inherits — the split pattern, the canonical roll assertion, the ADR-0014/plan-007:83 reconciliation, and the assertion-churn bar. It goes first specifically because data_usage_section.dart already contains a working reference implementation at :298-312, so the architect ratifies against a real example rather than a sketch.

10.2–10.4 are one file each and could parallelize in worktrees; 10.5 and 10.6 are independent of the gate entirely. The run stays sequential on main because each cycle’s gate runs the whole flutter test suite, which is cross-attributable in a shared tree (the plan-004/005/006 lesson), and 10.2’s ~12-assertion churn makes clean attribution especially valuable. The nested repo’s worktrees must be managed MANUALLY in any case.

Commit scopes: app (10.1–10.5), core (10.6), docs (10.7).

Relationship to the other plans. plan-009 cycle 9.3 corrects ADR-0014:66’s fade-span and is forbidden from touching the forward-lock — if it has landed, do not revert it. plan-008 sharpens PEAK, changing fixture values but not structure; a higher peak is intended and must not be filed as a regression in 10.2.

Common contract (applies to every session)

Architect gate: required (opus) on 10.1 ONLY; none on 10.2–10.7. 10.1’s verdict is the design authority for the plan. MODEL-TIER POLICY: architect gate + ALL REVIEW on opus; RED/GREEN/REFACTOR default sonnet; never haiku.

No cycle is security-tier — presentation only, no auth, secrets, PII or injection surface.

The RED phase carries unusual weight and every cycle’s REVIEW must verify it. The defect is that the existing assertions cannot distinguish a roll from a cross-fade. So a RED that asserts a rendered string is not merely weak here, it is the exact bug: it would pass on unmodified code. Every RED in this plan must be demonstrated to FAIL before GREEN, and that demonstration recorded in the cycle note. A RED that never failed is a BLOCKER.

Workflow execution. Cycles run via .claude/workflows/tdd-cycle.js ({ project: "u60-monitor", projectPath: "projects/personal/u60-monitor", plan: "010", cycle, greenAgent: "Flutter Expert", redAgent: "Flutter Expert", securityTier: false }). 10.7 is no-tdd and runs GREEN → REVIEW directly. Commits stay OUTSIDE the workflow.

Worktree convention

Not applicable — cycles run sequentially on main. (Harness note, carried from plan-004/007/008/009: isolation:worktree creates an app-less ROOT-repo worktree because /projects/ is gitignored at the monorepo root — the nested u60-monitor repo’s worktrees must be managed MANUALLY.)

Inter-batch verification

After each cycle: full flutter test green + flutter analyze clean + a fresh code-reviewer (opus) APPROVED; update the cycle status: in plan-010.yaml; file docs/cycles/10.X.yaml (npm run validate-cycle-note); regenerate docs (npm run build -- u60-monitor; html/ gitignored). One commit per cycle per commit.md.

Three checks specific to this plan:

  • git diff --stat lib/ui/widgets/animated_numeric_text.dart lib/core/numeric_transition.dart must be EMPTY for cycles 10.1–10.4. The primitive is correct; the call sites are wrong. A diff there means the cycle solved the wrong problem — and ADR-0014:184-186 explicitly rejects that solution. 10.5 is the single sanctioned exception.
  • Each cycle’s RED must be recorded as having failed on unmodified code. No demonstrated prior failure → the cycle proved nothing.
  • No genuine cross-fade surface was split. 'resets day N', elapsedLabel, uptime — each cycle confirms its own file’s legitimate cross-fades were left alone.

Stop conditions (across all batches)

  • A RED passes on unmodified code → BLOCKER. The assertion is measuring the rendered string, which is the blind spot that caused this defect.
  • The primitive is modified in 10.1–10.4 → BLOCKER. ADR-0014:184-186 rejects teaching it to parse combined strings; a scalar direction cannot tell '254%' from '3d 4h'.
  • A genuine multi-token cross-fade is split ('resets day N', elapsedLabel, uptime) → BLOCKER; the forward-lock reserves direction 0 for exactly those.
  • A 10.2 assertion rewrite merely re-pins the new strings → BLOCKER, not a NIT. That reproduces the original blind spot.
  • Semantics fragments on any split surface (a reader announcing '254' then '%') → BLOCKER.
  • 10.5’s measurement indicates the negative-x design is itself wrong rather than merely unbounded → STOP; that reopens an architect-locked ADR-0014 decision and needs a gate.
  • 10.5 asserts the backlog’s ~20-24px estimate instead of measuring → BLOCKER.
  • 10.6 becomes an axis redesign → STOP; log-vs-percentile ceiling is a separate plan.
  • A plan-009 correction is reverted (notably ADR-0014:66’s fade-span) → BLOCKER.
  • Any outer-size change or new overflow at 360dp / 1.3× on a split surface → BLOCKER.
  • Any dependencies: add (none planned) → out-of-bounds STOP.

Final state

Test trajectory: baseline 381 (or 382 after plan-009 / ~425 after plan-008) → roughly +6 (10.1) +5 (10.2, plus ~12 rewritten) +3 (10.3) +5 (10.4) +3 (10.5) +2 (10.6) ≈ +24, with ~12 existing assertions rewritten to prove strictly more than they did.

Every surface the ADR-0014 forward-lock governs actually rolls its digits: percent, PEAK, CAP, dBm, OF and the two volume readouts, each with the unit as a static sibling and Semantics still announcing one label. Genuine multi-token surfaces still cross-fade, now provably by design rather than by accident. The dropped-glyph overlay’s geometry is measured and asserted instead of assumed. _kHeadroom no longer exists as dead code that an ADR calls live. plan-007.yaml:83 no longer contradicts ADR-0014, and the ADR records why the failure was silent — the durable lesson, without which the same regression recurs on the next numeric surface added.

ZERO new deps. No git remote — never push.

Remaining: plan-011 (data truth + auth), a housekeeping plan, the root-monorepo items, and the human deploy pass — to which 10.5 returns only the “does it read graceful” half, the collision half now being settled in-repo.
