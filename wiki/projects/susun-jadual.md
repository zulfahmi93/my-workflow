# Susun Jadual

**Status:** Plan-001 v2 drafted 2026-05-19 after a 3-Opus-agent roundtable critique (architect + PM + UX). **25 TDD cycles + Phase 0 scaffold + Phase 0.5 Discovery + Phase 7 Pilot launch.** Zero cycles shipped. Web-only MVP scope: no bot, no NL parser, no monetisation gate. See [[susun-jadual-roundtable-2026-05]] for the multi-POV synthesis behind v2.

## What

AI-assisted school timetable generator for Malaysian sekolah rendah (primary) + sekolah menengah (secondary). Replaces RM2,800–3,400 single-PC incumbents (ASc Timetables, iLeague) used 2–3×/year by every M'sia school. User flows: web setup wizard → click "Generate" → durable Hangfire job → solver returns timetable → view + PDF export.

## Why

**Customer pain:** RM3,000 / single PC / single school / used few times a year = wasteful. Per-PC licence locks IT-savvy admin to a physical machine. Setup UX in incumbents is hostile (200+ checkboxes across 12 tabs). No mobile or web access. Heads-of-school can't review timetables on phone.

**Honesty framing (load-bearing):** "AI-assisted" means LLM helps with natural-language rule entry (plan-002). The **timetable itself is generated by a deterministic CSP solver (OR-Tools CP-SAT)**, not an LLM. LLMs cannot guarantee no-teacher-conflict across 900+ cells; CP-SAT can. Customer-facing copy MUST NOT imply LLM scheduling. Reviewer flags violations as `[BLOCKER]` (see `projects/susun-jadual/CLAUDE.md §"Honesty boundary"`).

## Core domain concept

[[timetable-csp]] — timetable scheduling as a Constraint Satisfaction Problem; hard constraints (teacher / class / room non-conflict, hours allocation, qualification, load bounds, parallel Islam/Moral split) vs soft (PE not last period, no >3 consecutive teaching, balanced teacher load); OR-Tools CP-SAT chosen as the solver; independent `verify.py` re-checks every solver result.
